Your browser, your components

Skiff keeps the browser engine, sessions and native pages in a small host. Stock and local components provide the interface and replaceable behavior. You can change one part without replacing the rest.

Everyday browser tools

Open Browser Tools through the command menu, or run:

bin/skiff ui.openTools '{"section":"settings"}'
bin/skiff commands.list
bin/skiff settings.catalog '{"query":"memory"}'

The tools sections are settings, history, downloads, profiles, folders, sites, sync, components, grants, transcripts, page and commands. The live command catalog includes input schemas. Use it rather than guessing optional fields.

settings.catalog entries carry what an interface needs to draw them: title, description, type (boolean, number, integer, string or action), the current value, the allowed values of a choice (enum) and, for an action, its actionLabel, host-computed status text and available. settings.run {"id":"defaultBrowser"} runs an action; an action this platform cannot run is not listed. Entries with quickPanel:true are the ones a shell draws in its quick Settings panel (settings.catalog {"quickPanel":true,"owner":"core"}), so a shell that draws that list shows new host settings without a code change.

  • Find and reader: find tracks matches in the current document. Reader extracts an article into a reversible view without navigating the original page or losing its sign-in. Not every page is an article.
  • Split and peek: place two tabs side by side and adjust their divider. User link peek is temporary; promote it to retain a tab or dismiss it. It is separate from showing an agent's hidden working tab.
  • History and downloads: search, reopen or remove normal browsing history. History is profile-aware and bounded, with a 90-day default. Downloads expose progress, cancellation and open/reveal actions. Clearing records does not delete downloaded files. A private download can still save a file when you explicitly choose to download it.
  • Profiles and routing: create isolated profiles and choose a space's profile for future tabs. Moving an existing tab does not change its cookies or session. External-link rules select where links open.
  • Folders and trails: folders are durable entities, including empty and nested folders. Collapse folders or parent-tab trails without deleting their contents.
  • Site controls: permission decisions are scoped by profile and exact origin. Choose once, session or remembered decisions where offered; revoke remembered decisions in Sites. Zoom is also remembered per profile and origin. Private decisions and zoom do not persist.
  • Command bar: commands, settings and history are discoverable alongside destinations. Searching local metadata does not itself submit a web search.
bin/skiff ui.openFind
bin/skiff find.update '{"query":"example","matchCase":false}'
bin/skiff find.next '{"forward":true}'
bin/skiff find.close
bin/skiff ui.openReader
bin/skiff reader.close

Discover, copy, edit, check, preview, apply

Use Components to inspect the actual selected source, its file list, capabilities, active revision, errors and copy provenance. ui.inspectSource resolves a role in the active space by default and reports its selected owner, source and file. Pass spaceId:null to inspect the global binding, or a normal space ID to inspect that space. ui.customize accepts the same scope and creates an owned copy, then opens it in Components. The Role selector includes additive manifest surfaces, not only stock role names.

bin/skiff components.list
bin/skiff ui.inspectSource '{"role":"launcher"}'
bin/skiff ui.inspectSource '{"role":"launcher","spaceId":null}'
bin/skiff ui.customize '{"role":"launcher"}'

For a deterministic behavior example, copy the bundled search component. The returned path is the editable workspace, not the active revision directory.

bin/skiff components.create '{"id":"local.search","from":"stock.search"}'
bin/skiff components.inspect '{"id":"local.search"}'
bin/skiff components.source.read '{"id":"local.search","file":"backend.js"}'
# Edit the returned workspace files in your editor.
bin/skiff components.check '{"id":"local.search"}'
bin/skiff components.preview '{"id":"local.search"}'
bin/skiff components.apply '{"id":"local.search"}'
bin/skiff components.bind '{"role":"search","id":"local.search"}'

Checking validates the manifest, files and backend syntax; it does not execute the backend or prove its behavior. Preview uses an isolated disposable profile with backends disabled. A backend-only package has no UI to judge in preview. Preview is not a test of production cookies, permissions or backend effects.

Applying is an explicit trusted local action with native approval. Review the source and capabilities first. The host binds approval to the exact candidate revision; a changed workspace or snapshot requires review again instead of silently applying different code. expectedRevision is supported by apply, enable and revert for revision-bound callers. Do not invent a hash: use the inspected candidate or previous revision appropriate to the operation.

A successful apply replaces that component's active generation. It does not automatically select every role it provides. Bind the desired role explicitly. Bindings are independent and can differ per space:

bin/skiff components.bind '{"role":"search","id":"local.search","spaceId":"YOUR_SPACE_ID"}'
bin/skiff components.resolve '{"role":"search","spaceId":"YOUR_SPACE_ID"}'
bin/skiff components.revert '{"id":"local.search"}'
bin/skiff components.disable '{"id":"local.search"}'
bin/skiff components.enable '{"id":"local.search"}'

Replace launcher, frame, tab list, spaces, layout, overview, settings or chat independently when a package provides that role. Search, layout and archive behavior also use replaceable commands. A valid active per-space binding takes precedence over a valid global binding. A missing, inactive or unsupported per-space owner falls through to the global owner, then an explicit fallback or the first active stock provider in the host's deterministic registration order. Stored custom bindings remain intact, including in safe mode; fallback never implicitly enables a disabled stock component. Source inspection and host rendering use this same resolver. A component cannot seize a core command through load order. Revert selects the previous working revision and its configuration, not an undo of webpage activity or component data writes.

To import a local package, use components.check {"path":"/absolute/package/path"}, then components.stage with the same path. Staging does not activate it. Replacing an editable workspace through staging preserves the previous source at the returned sourceBackup. Source edits invalidate the candidate until it is prepared again.

A package is ordinary local source

No package manager SDK or frontend framework is required. A package has a manifest.json, relative surface files and an optional CommonJS backend. This example matches the search package API, with a user-owned ID:

{
  "apiVersion": 1,
  "id": "local.search",
  "version": "1.0.0",
  "surfaces": {},
  "backend": "backend.js",
  "roles": ["search"],
  "commands": { "search": "local.search.run" },
  "dataVersion": 1,
  "capabilities": ["backend", "commands.register", "call:host.search"]
}
'use strict'
exports.activate = async (api) => {
  await api.register({
    name: `${api.id}.run`,
    description: 'Resolve an entered destination',
    inputSchema: {
      type: 'object',
      properties: { text: { type: 'string' } },
      required: ['text'],
      additionalProperties: false
    },
    tool: false,
    run: ({ text }) => api.call('host.search', { text })
  })
}

Command names belong to the package namespace. Inputs are schema-checked by the shared registry. Registration can include descriptions, titles, aliases, output schemas and explicit tool metadata. Await registration during activation so failures are reported as activation failures.

Arbitrary surfaces

Surfaces are not limited to built-in roles. For example, a package named local.notes can declare "surfaces": {"notes":"index.html"} with "capabilities":["ui"]. Add only the call:COMMAND and events:EVENT capabilities its scripts actually need. Declare those capabilities in the manifest and approve them on apply.

bin/skiff ui.showSurface '{"id":"local.notes","surface":"notes","name":"my-notes","bounds":{"x":40,"y":60,"width":440,"height":500},"focus":true}'
bin/skiff ui.closeSurface '{"name":"my-notes"}'

Showing the named surface again updates its placement. Bounds are native-window CSS coordinates. The host reserves Escape to close the focused overlay and return focus to the live page or main window, even if custom JavaScript does not implement dismissal. Find and reader also close their associated native state.

A surface is a real local renderer, not webpage-injected markup. Its external scripts use window.skiff.call(name, params) and window.skiff.on(event, listener). The host validates the sender's component ownership and capabilities. Normal websites never receive this bridge. Follow the local renderer CSP, use external scripts and styles, and render untrusted titles and URLs as text.

Stock and owned UI use the same capability-checked bridge; a stock. name grants no special RPC or event bypass. The bundled management UI explicitly declares host.manage, call:* and events:*. An owned copy gets those capabilities only through the normal native approval flow.

host.manage is powerful local administration. It allows management endpoints such as grants, sync, imports and component activation when combined with the required call capability. call:* alone does not authorize these operations. Do not add host.manage merely to read or write a component's own preferences. Source, storage and settings convenience APIs remain owner-scoped; explicit administrative calls with an ID can manage other components. An originating agent's access context still limits nested calls, even through a management component: the component cannot use that invocation to grant the agent more credentials. This is host API authorization, not an OS sandbox for local Node code.

Backend lifetime and authority

activate(api) can return a disposer function or an object with dispose(); a module-level dispose is also supported. api.register returns a promise for an idempotent unregister function. api.on(event, callback) returns an idempotent unsubscribe function. Either function can be returned from activate as its lifecycle disposer and safely called during shutdown, including after the host has removed the component's commands and listeners. Genuine backend disposal errors still propagate. Command handlers receive {signal} for cancellation.

Backends run in supervised Node child processes. Replacing, disabling or removing a component disposes its commands and listeners, cancels old work and tears down its process group. Late replies from a retired generation cannot update the active generation. Activation failure is reported and the prior working revision is restored when possible. A disposer should release resources promptly and must not depend on new host calls after shutdown has begun.

If a component manager replaces itself, its old UI may disappear before it receives the command reply even though the approved replacement completes. Inspect the active revision from the replacement UI or native Recovery manager rather than assuming a missing reply means nothing changed. Independent agent-grant revocation still cancels authorized work. Lifecycle cancellation is rechecked when queued work begins and during replacement; recovery attempts to restore the prior generation. If disabling and recovery both fail, the component is durably disabled and the error remains visible.

Trusted Node is not an OS sandbox. Backend code can use Node filesystem, process and network APIs with your account's authority. Manifest capabilities limit the Skiff bridge, not arbitrary Node access. Install only source you trust. The worker boundary contains lifecycle failures; it is not a security boundary against malicious local code.

Settings with a clear owner and scope

A component can declare scalar settings in its manifest and must include storage in its declared capabilities. Keys are simple names without dots. Each definition declares a type and default; scope is global unless explicitly set to space. For example, add this field to a package manifest and approve its storage capability:

"settings": {
  "compact": {
    "type": "boolean",
    "default": false,
    "scope": "space",
    "title": "Compact layout",
    "description": "Use less vertical space in this component.",
    "aliases": ["density"],
    "section": "appearance"
  }
}

Supported types are string, boolean, number and integer. Definitions can constrain values with minimum, maximum, maxLength, pattern or enum where appropriate. A declared setting is configuration, not executable behavior: the component must actually read and use it.

bin/skiff components.settings.list '{"id":"local.search"}'
bin/skiff components.settings.get '{"id":"local.search","key":"compact","spaceId":"YOUR_SPACE_ID"}'
bin/skiff components.settings.set '{"id":"local.search","key":"compact","value":true}'
bin/skiff components.settings.set '{"id":"local.search","key":"compact","value":false,"spaceId":"YOUR_SPACE_ID"}'
bin/skiff components.settings.reset '{"id":"local.search","key":"compact","spaceId":"YOUR_SPACE_ID"}'

These examples require that the package declares compact. Omit spaceId to edit the global override. A space-scoped setting resolves in this order: manifest default, global override, normal-space override. Reset removes the override at that scope so the inherited value becomes visible. Global-only settings reject space overrides; private-space persistence is rejected.

Resolved entries expose id as OWNER.KEY, plus owner, key, value and source (default, global or space). Shared Settings and catalog search use this metadata, so a setting's owner and effective source remain visible. Properties live in composition metadata, not source files. Disable retains them; apply carries compatible current overrides and records the outgoing configuration. Revert restores the previous revision together with its saved property overrides, rather than imposing the latest configuration on older code. The target configuration is validated before replacing the active generation. Incompatible values are rejected rather than silently coerced or dropped. Versioned component storage remains unchanged: reverting configuration is not a rollback of arbitrary data writes.

components.inspect also exposes the retained properties override map. components.resolve identifies the selected role owner and whether the binding came from global or space; explicit or stock fallback has source default. Use these existing inspection and binding commands together with components.settings.* to understand a composition. There is no separate composition-editing command family.

Revert swaps the current and previous code/configuration snapshots, so reverting again can return to the revision you just left. This does not undo filesystem, network or other external side effects performed by trusted backend code.

With the storage capability, a backend uses its own api.settings.list/get/set/reset methods and can subscribe to api.on('settings.changed', callback). This notification is permitted by the storage grant. Settings do not require a separate private configuration file or a second UI convention.

Source, data and recovery belong to you

The profile directory is selected by SKIFF_DATA, or defaults to the platform's Skiff application-data directory. Browser state, sessions, component workspaces and component data have different jobs. Back up the entire closed profile before moving it; copying only state.json does not copy cookies or component packages. OS-encrypted secrets may not unlock on another machine.

  • Bundled source: stock packages are read-only through component editing APIs. Copy before changing them. Copies record their origin, active base revision and actual copied source revision. A copy also records its stock (origin.id, origin.stockRoot) and a hash of its own source (origin.sourceHash). At startup and when a stock is refreshed, a copy whose workspace and active revision still match that hash follows a changed stock: it is rebuilt from the new stock source and activated, with the previous revision kept for components.revert. A copy you edited, a copy that would need capabilities it was never granted, a copy of a workspace component and a migrated legacy import are never rewritten.
  • Workspaces and revisions: editable files are separate from immutable active snapshots. components.inspect exposes paths and revision metadata. Do not edit revision directories directly.
  • Component data: lives outside source under components/data/ID/vVERSION/global or spaces/SPACE_ID. Removing a package retains data unless deleteData:true is deliberately requested.
  • Legacy shell migration: an existing data-dir shell is backed up, imported as owned legacy.shell source and selected during migration without replacing unrelated custom selections. Safe mode skips legacy import.

stock.shell points to the selected bundled shell, not a permanent data-dir copy. A fresh installation follows bundled updates. ui.shellPath returns {path,owner,readOnly}; when readOnly is true, customize before editing. Switching with ui.setShell chooses a bundled variant and replaces stock or legacy global role selections, retaining independent custom and per-space bindings. ui.resetShell selects the default stock, Layer, and backs up the original data-dir shell if it remains; the owned legacy package is retained. Neither operation rewrites user-owned component source.

With the storage capability, a backend can use:

await api.storage.write('preferences.json', { compact: true })
const preferences = await api.storage.read('preferences.json')
await api.storage.write('preferences.json', preferences, { version: 2 })
await api.storage.remove('preferences.json', { version: 1 })

The default version is manifest.dataVersion, or 1. A version change selects another namespace; it does not automatically migrate data. Implement and review migration explicitly, retaining old data until the new version is usable. Optional spaceId scopes data. Private-space storage and writes marked private:true are rejected. Do not bypass that policy by writing private data to a global key. With the source capability, api.source.read(file) and api.source.write(file, content) operate on the owned workspace, not live source activation.

Recovery does not depend on your replacement UI

The native Recovery menu can enter safe mode, open the stock component manager or reload selected UI. Safe mode uses stock UI and disables custom execution while retaining tabs and sessions. You can also start the application with --safe-mode, for example npm start -- --safe-mode. Inspect or disable the broken package, then restart normally when ready; custom components cannot be enabled while safe mode is active.

If composition metadata is corrupt, normal startup preserves it and requests safe mode. Safe mode copies the exact bad file to components/recovery/composition-UUID.json before making a stock-only composition. User source and data remain on disk. Inspect metadata exposes the recovery error, backup and time. Preserve that backup before manually restoring any custom bindings. Safe mode is recovery from configuration or UI failure, not an undo for arbitrary trusted backend filesystem effects.

Agents need explicit grants

Configure an ACP process in Agents. It uses its own credentials. Including a page is an explicit choice, separate from allowing browser tools. Skiff does not automatically capture pages for AI. Incognito pages cannot be included or accessed through browser tools.

In Grants, select the agent, the tabs or spaces it may access, read and mutation rights, and any optional component tools. A grant is not permission to use the owner API. Session credentials are restricted to POST /mcp; they cannot read owner /events or call /rpc. Revoke a grant to invalidate its derived session credentials. Agent permission cards remain additional requests from the agent, not an expansion of Skiff access.

bin/skiff grants.issue '{"owner":"my-agent","tabIds":["YOUR_TAB_ID"],"read":true,"mutate":false,"tools":[]}'
bin/skiff grants.list
bin/skiff grants.revoke '{"owner":"my-agent"}'

The issue result contains a credential: do not paste it into public logs. The owner token in api.json is more powerful and must not be substituted for it. Grants are not an OS sandbox for the agent process itself.

The owner token has different authority on different routes. Owner /rpc remains fully trusted local control. Owner-token /mcp is limited to normal-browser commands: it excludes private, temporary and orphaned tabs, with authorization checked before and after asynchronous work. Its request-only browser context is not a selectable grant or a reusable session credential. It does not expose customization, management or implicit component tools; those still require explicit scoped grants. This narrower MCP behavior does not make the owner token safe to share, because the same token still authorizes owner RPC.

Browser tools

A Read grant lists and reads tabs (browser_list_tabs, browser_read_page). A Mutate grant opens, navigates, shows and closes them (browser_open_tab, browser_navigate, browser_activate_tab, browser_close_tab) and drives a page: browser_snapshot (the interactive elements with short refs like e12), browser_click, browser_type, browser_press, browser_scroll, browser_screenshot and browser_wait, plus browser_request_tab (ask the user for a tab) and browser_finish (mark a tab done). They are the registry commands tabs.snapshot, tabs.click, tabs.type, tabs.press, tabs.scroll, tabs.screenshot, tabs.wait, agent.requestTab and agent.finish, so the owner CLI calls them too. A grant's agent acts under its own name and drives only tabs it opened with browser_open_tab or that the user handed to it; the same rule holds for the owner CLI, where each call names its agent. Input goes through the tab's own DevTools channel and never moves the operating system's focus, mouse or keyboard. The tab shows a control layer with the agent's cursor and a Take over button, and the user's mouse and keys to that tab are held back while the agent works. After a take-over the agent's calls fail with user_has_control.

Component commands become potential agent tools only when explicitly marked tool:true; the user must also select their exact names in tools on the grant. A custom tool's nested api.call browser operations retain the authenticated caller's tab/space and read/mutation limits. Revoked, cancelled or unrelated invocation requests are rejected. Independent backend background work instead uses the component's explicitly granted capabilities. This distinction does not make an untrusted Node backend safe.

Select a grant, do not silently combine grants

Read and Mutate are independent choices, both off by default. A mutation-only grant does not imply reading, and a tools-only or customization-only grant needs neither browser right. Browser rights require selected normal tabs or spaces. Creating a grant does not select it for an agent or combine it with existing grants. Choose Use for agent, or call grants.select with the returned grant ID:

bin/skiff grants.select '{"id":"YOUR_GRANT_ID"}'
# To select it for one chat instead:
bin/skiff grants.select '{"id":"YOUR_GRANT_ID","sessionId":"YOUR_CHAT_ID"}'

Grant metadata lists selectedFor, containing null for the owner's general selection or individual chat IDs. Revoking a selected grant does not secretly fall back to a broader grant.

Ask an agent to customize only the selected component

The component inspector's customization action lets you pick an agent and confirm the exact owned component scope. For bundled stock source, it makes an owned copy first. It then selects a customization-only grant and starts a chat with source context and includePage:false. This is deliberate source sharing, not automatic page capture.

bin/skiff grants.issue '{"owner":"my-agent","read":false,"mutate":false,"tools":[],"components":["local.search"]}'
bin/skiff grants.select '{"id":"YOUR_RETURNED_GRANT_ID"}'

components contains exact authorized component IDs. It is separate from tools, which grants invocation of explicitly tool-enabled component commands. Through scoped MCP, a customization grant permits filtered components.list, inspect, source.read, source.write, check, preview, create, apply, enable, revert and bind operations for its authorized packages. Use the full components. command prefix. Checking is by ID only, not an arbitrary filesystem path.

Copy creation requires an authorized from source. The destination must be an exact approved ID or a fresh child of the grant's returned componentNamespace, which is custom.ROOT_GRANT_ID. Successfully created IDs join that grant's ownership. Stock source cannot be mutated: copy it first. The grant does not expose unrestricted staging, unrelated source, arbitrary paths, removal or component storage.

Apply, enable and revert still require native approval. The host pins the approved revision; an agent cannot bypass consent by supplying an owner token or choosing a different revision afterward. Revocation invalidates derived session credentials and later work. Even a tightly scoped customization grant can prepare trusted Node code, so review the source and requested capabilities before activation.

Transcripts are local records, not hidden memory injection

Local recovery transcripts are off by default. Enable transcriptRecovery to save normal conversations; transcriptRetentionDays sets retention, initially 30 days. Saved transcripts support search, export and deletion. ACP may restore its own session. If it cannot, Skiff shows a saved local transcript as read-only recovery and requires a fresh session to continue. The recovered messages are not secretly sent to that new session. Private chats do not produce local transcripts, though the external agent can keep its own history.

Export is deliberate disclosure. A transcript can contain prompts, page excerpts, tool results and secrets you supplied. Keep exports private; deletion in Skiff does not remove exported files or an agent provider's records.

Manual, opt-in encrypted sync

Sync has no hosted account or automatic background schedule. Supply your own shared folder transport or HTTPS WebDAV endpoint, pair devices with the same high-entropy key, then choose Sync now on each device. The local folder contains encrypted payloads; your separate folder-sync software is responsible for transporting them.

# On the first device:
bin/skiff sync.configure '{"transport":"folder","directory":"/absolute/shared/skiff"}'
bin/skiff sync.key.create
bin/skiff sync.key.export
bin/skiff sync.now

# On another device, configure its path to the same shared folder, then:
bin/skiff sync.key.import '{"key":"YOUR_EXPORTED_PAIRING_KEY"}'
bin/skiff sync.now
bin/skiff sync.status

For WebDAV use sync.configure with transport:"webdav", endpoint, and optional username/password. Keep credentials out of endpoint URLs. HTTPS is required except loopback development endpoints. WebDAV must support the conditional writes used to avoid silently overwriting concurrent changes. Avoid putting real secrets into shell history; prefer the local Sync form.

Payloads use AES-256-GCM with fresh nonces and versioned authenticated context. Portable records include spaces, profiles, folders, ordinary and archived tabs, and an allowlisted set of preferences. Profile identity is portable, not its signed-in session. Cookies, passwords, private and agent-only tabs, local transcripts, component source, native machine paths and browser credentials are not transferred. Local-service and credential-bearing URLs are excluded; this is not a complete browser-profile backup.

Closing or auto-archiving an ordinary tab syncs its archived state, not a permanent deletion. Restoring it keeps the same logical ID and the device-local profile partition. Archived records survive removal of their old space and can restore to a fallback space. Removing an archive entry or clearing the archive permanently removes records that are no longer live and creates tombstones. A permanent deletion wins against an offline device's stale restore; sync does not invent a replacement ID to resurrect it. The same privacy exclusions apply to both live and archived tabs.

Record clocks and deterministic device tie-breaks resolve conflicts; permanent deletions use tombstones and take precedence against competing records. Conflicts are listed in status. This is not a text merge editor or a manual choose-every-winner dialog. Review the outcome, make the intended local edit and sync again. Folder transport uses separate device records; WebDAV retries conditional conflicts rather than blindly replacing another writer. Network or authentication failure leaves browser records unapplied.

Where a protected OS storage backend is available, Skiff seals the local pairing key and credentials. Without one, it does not fall back to plaintext key storage: after each restart use sync.unlock with your pairing key and, if needed, WebDAV credentials. A weak plaintext OS backend is not treated as protected storage. There is no hosted key recovery. Keep a deliberate private copy of the pairing key; losing it can make encrypted data unrecoverable.

sync.key.export reveals the decryption key. Anyone with that key and the remote payload can read the synchronized records. sync.disable stops sync without deleting browser data or claiming to erase copies on other devices. Encryption does not hide transport metadata from the server, and a shared folder's path or WebDAV endpoint remains local configuration.

Memory saver and honest limits

Memory saver is off unless enabled in settings. It considers idle background pages and refuses to discard pages that are visible, active, loading or protected by activity such as forms, media, downloads, permissions, reader/find use or unreported frames. Private, chat, agent and user-peek tabs are excluded. Conservative protection can keep a page loaded longer than expected.

bin/skiff settings.set '{"memorySaver":true,"memorySaverMinutes":30}'
bin/skiff tabs.discard '{"id":"BACKGROUND_TAB_ID"}'
bin/skiff tabs.recover '{"id":"TAB_ID"}'

Discard destroys the renderer, not the tab record or profile session. Waking it reloads the URL. Skiff does not serialize arbitrary JavaScript state, guarantee scroll restoration or promise recovery of unsaved page work. Cookies remain in the session. A crashed-page reload has the same distinction: the browser can reload a tab, not resurrect a lost renderer's memory.

The initial isolated Linux Electron smoke exercised find, reader, split, peek and history while preserving the existing page and cookie. That evidence does not establish every native scenario, every component failure path or macOS behavior. Broader review and native acceptance remain separate from this guide. No live Mac rollout is implied.
