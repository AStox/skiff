## Shell & Command Reliability
1. **[2026-11-11] Electron 45 has no postinstall download**
   Do instead: run `node node_modules/electron/install.js` only when a new isolated install needs its binary before the first `npm start`; preserve an existing managed runtime during source updates. Run `npm test`, not `node --test test/`, on Node 22.
2. **[2026-11-13] Electron `session.fetch` responses have an empty `.url`**
   Do instead: use `net.request` and follow its `redirect` events when the final URL matters, as `pageFetch` in `src/main.js` does.
3. **[2026-11-13] An HTML drop is refused unless `dragenter` is accepted too**
   Do instead: call the same handler on `dragenter` and `dragover`. When the pointer lands on a new element Chromium fires only `dragenter`, and a release then never fires `drop`. In Playwright drags, move to the drop point in one step; passing other rows leaves the preview where it first appeared.
4. **[2026-11-20] Alternative shells live in `shells/<name>/`; owned shells must survive deployment**
   Do instead: preview bundled shells with `node scripts/shell-preview.js shells/<name> out.png` using synthetic state, then exercise them under Linux/Xvfb. Stock components follow bundled revisions; owned and migrated legacy source remains independent. Preserve the selected shell and custom bindings on deployment; do not call `ui.setShell` or reset/delete live source merely to expose new host features. Browser Tools and Recovery are available through the native menu.
5. **[2026-11-17] Under Xvfb the desk window composites in software at about 30 fps, a frame or two behind main-process `setBounds`**
   Do instead: sample view motion in the main process (`global.__skiffVisualMoves` in `e2e/electron-entry.js`) and read `ffmpeg -f x11grab -framerate 60` grabs only coarsely. `webContents.sendInputEvent({type: 'mouseWheel', deltaX, deltaY})` reaches the page with both DOM deltas of the opposite sign (deltaY verified 2026-11-18 in `e2e/expose.spec.js`), so send `-x, -y` for a DOM swipe; DOM `deltaY > 0` is fingers moving up under natural scrolling.
6. **[2026-11-17] `webContents.sendInputEvent` mouse events carry no screen position or held button by themselves**
   Do instead: pass `globalX`/`globalY` (they become DOM `screenX`/`screenY`, unscaled by page zoom) and `modifiers: ['leftButtonDown']` on each `mouseMove` of a drag; `pointer()` in `e2e/desk.spec.js` does both and follows a view that moves under the pointer.
7. **[2026-11-17] Asking the agent needs a real ACP agent outside Electron, and `nobody` cannot reach Adam's omp credentials**
   Do instead: e2e sets `settings.set {ai: {agents: [{name: 'Fake', command: "'<node>' '<repo>/e2e/fake-agent.js' '<fixture root>'"}]}}` (the root makes its processes findable with `ps`; it saves sessions in `<data>/ai`, so `session/load` works after `skiff.restart()`). For the real harness, as root with `HOME=/root SHELL=/bin/bash`, `createAi` from `src/ai.js` in a throwaway Node script with a stub `state()` listing the agent and a stub `pageText`; delete the script after. Without `SHELL` the agent runs under `/bin/sh -lc`, which does not exec the command, so only the process-group kill in `stop()` ends it.
8. **[2026-11-17] Chat tabs are views with the shell bridge but not shell pages, and a desk shell's window is not `getAllWindows()[0]`**
   Do instead: anything pushed to "every page with `window.skiff`" goes to `chatContents()` as well as `shellContents()` in `src/main.js`. In specs find the window by `webContents.getURL().endsWith('/index.html')` (the fixture's `barOpen` does); index 0 can be another window after a switch to Layer and answers wrongly without failing. A focused closed `<select>` takes ArrowDown/ArrowUp as a value change (with `change`) on Linux, so keyboard picks need no popup; a mouse click opens the popup without a page `blur`.
9. **[2026-11-18] `capturePage()` on a `WebContentsView` that is not in a window never settles, and Playwright hides background rendering bugs**
   Do instead: capture only views attached right now (`shown` in `src/main.js`, as `tabs.thumbnails` does; agent tabs are attached to their hidden window) and treat the rest (hidden desk windows, other spaces) as no picture; an awaited capture of a detached view hangs its caller forever without an error. Check hidden or background rendering on an Electron spawned without Playwright (its debugger keeps pages rendering) and drive it over `api.json` + `/rpc`, as the last test in `e2e/agent-tabs.spec.js` does. Under Xvfb a view never in a visible window gets no frames; `wake` in `src/main.js` (an unpainted add/remove in the visible window after `dom-ready`) fixes it, and a repainting page then gets about 1 frame a second.
10. **[2026-11-18] Hiding a float overlay destroys its window, so its page cannot act after asking for that**
   Do instead: let the base page (`shells/layer/layer.js`) close and pick for a float overlay (the tab list sends `buoyAction('list-close')` and `buoyAction('pick')`), never `closeOverlay` from inside it. In specs a key that closes it rejects on key up (`.catch`), and each opening is a new page (filter `!isClosed()`). To put "another app" in front under Xvfb, open and `focus()` a plain `BrowserWindow` and destroy it only while the desk window has focus; `desk-activated` ignores focus within 400ms of `ui.raise`, so wait past that.

## Domain Behavior Guardrails
1. **[2026-11-20] The selected component source may be owned, not the bundled shell**
   Do instead: inspect `ui.shellPath` and `components.inspect` before changing UI source. Preserve legacy source and bindings; never delete profile shell files or call `ui.resetShell` as an update step. Use an isolated synthetic profile to validate new bundled components.
2. **[2026-11-11] Arc's real data is `~/Library/Application Support/Arc/StorableSidebar.json` and changes while Arc runs**
   Do instead: check importer output against a fresh count from that file, and print counts and names only, never his URLs.
3. **[2026-11-11] The HTTP API refuses any request with an `Origin` header or a foreign `Host`**
   Do instead: keep that check and the bearer token; it is what stops web pages from reaching the command API.
4. **[2026-11-13] Chromium accepts some broken icons with no error at all and draws nothing**
   Do instead: draw the image on a small canvas and look for a visible pixel. For an ICO whose BMP height is not doubled, `load` fires, `naturalWidth` is set and `img.decode()` resolves, so none of them proves the icon shows.
5. **[2026-11-14] Floating HTML over the native page: a transparent `WebContentsView`, not a dialog**
   Do instead: `new WebContentsView({ webPreferences: { ...shell prefs, transparent: true } })`, `setBackgroundColor('#00000000')`, add it last to `win.contentView` with the full content size; `html, body { background: transparent }` even with `color-scheme: dark`. Keep the page view at index 0 (`addChildView(view, 0)`) so re-attaching a page never covers the overlay. Await `loadFile` before sending it an event, or the first event is lost. `ui.showOverlay`/`ui.hideOverlay` in `src/main.js` are the implementation.
6. **[2026-11-15] Any `session.webRequest` listener silences every extension's `chrome.webRequest` in that session**
   Do instead: keep `src/main.js` free of `session.webRequest`; in e2e, `SKIFF_VISUAL_EXTENSIONS=1` blocks the outside world with a dead proxy (`setProxy`) instead of the request blocker. Extension pages run with `contextIsolation: false`, so a session preload (`registerPreloadScript`) patches `chrome.*` directly; Chromium also exposes a separate `browser` object there and uBO prefers it, so patch both and share event objects. Electron never fires `tabs.on*`, has no `webNavigation`, `windows`, `browserAction`, `privacy`, `tabs.create/remove/insertCSS`; `src/extensions.js` supplies them from the views. uBO needs `webNavigation.onCommitted` for a tab before it filters that tab at all; without it everything is "behind the scene" and nothing is blocked. EasyList has `@@://127.0.0.1$generichide`, so test cosmetic filtering on `lvh.me:<port>` (resolves to 127.0.0.1), never on 127.0.0.1 or nip.io. Chrome sizes popups to content: lay out narrow for the width, then measure body children bottoms for the height (`documentElement.scrollHeight` is the viewport when html is 100% tall).
7. **[2026-11-15] An unpacked extension's id and storage follow its folder path, so replacing the folder in place is an update**
   Do instead: `extensions.update` (and the 6-hour timer in `src/extensions.js`) swaps `<data>/extensions/<slug>` under the same path; `removeExtension` + `loadExtension` keeps `chrome.storage.local` and IndexedDB (uBO's "Blocked since install" counter carried over). Never clear storage on replace. A page loaded within about a second of the swap shows uBO's "Could not filter properly at browser launch" note, as Chrome does after an update; that is timing, not a bug. Test the updater against a local release page (`SKIFF_BUILTIN_EXTENSIONS='[{"name":"uBlock Origin","release":"http://127.0.0.1:<port>/release"}]'`, JSON `{tag_name, assets:[{name:"x.chromium.zip", browser_download_url}]}`); e2e sets `SKIFF_BUILTIN_EXTENSIONS='[]'` by default so no run talks to GitHub. Root grabbing nobody's Xvfb with `ffmpeg -f x11grab` needs `XAUTHORITY=` the `-auth` file from the Xvfb command line.
8. **[2026-11-16] In a desk window the shell page lies under every page view, and an overlay is one bounded view**
   Do instead: put nothing the user must reach where a page can lie; `shells/layer` slides, narrows, hangs or tucks ears and keeps windows above the Buoy's strip. Size overlays to their content (the layer opens them window tall, they trim themselves) and close transient ones (the command bar) on `blur`, since a bounded overlay never sees the outside click; the panel is pinned in its own `panel` overlay (shown with `focus: false`), closes only by Cmd+S, the Buoy or its close button, and its view rect is an ear occluder. [2026-11-17] Iterate with `scripts/shell-preview.js` desk mode; in the real app under Xvfb there is no compositor, so transparent pixels grab as black.
9. **[2026-11-16] Xvfb has no window manager, so a float overlay's always-on-top level and workspaces do nothing there, and any focused window is raised over it**
   Do instead: check `setAlwaysOnTop`/`setVisibleOnAllWorkspaces`/`focus` by the calls `e2e/electron-entry.js` records. For real X input (XTEST: moves, presses, wheel buttons 6 and 7) there is no xdotool or pip on Hetzner: unzip the python-xlib wheel from PyPI into a scratch dir and use `Xlib.ext.xtest.fake_input`; after the desk window takes focus, `raise_window()` the float's `getNativeWindowHandle()` XID again, as a real window manager would keep it above. macOS desktops are faked the same way: `fixtureOptions.desktops: [3, 1]` makes `e2e/electron-entry.js` swap `src/desktops.js` for a provider and `global.__skiffDesktops.switchTo(id)` (main process) changes the current one; the real koffi path runs only on a Mac and is never started in e2e. [2026-11-23]
10. **[2026-11-17] Under Playwright a page never gets a window `focus` event when its view takes the keyboard**
   Do instead: after `ui.showOverlay {focus: true}`, `ui.emit` an event (`ai-shown`, the command bar's `new-tab`) and focus the field in its handler; never rely on `addEventListener('focus')` in an overlay. Check the field with `toBeFocused()` and the view with `webContents.isFocused()`.
