# Skiff

A local-first Arc-like browser for macOS, built on Electron. Three layers:

1. **Host** (`src/main.js`, `src/state.js`): owns browser sessions, native page views and persistence behind one typed command registry.
2. **Components** (`components/`, `shells/layer/`): stock and user-owned HTML/CSS/JS surfaces and optional local backends. Roles can be replaced independently, globally or per space, without replacing live webpages.
3. **Local API**: the same registry over HTTP on 127.0.0.1, plus a CLI. The owner API controls the browser; agents receive only explicitly approved scopes.

Web pages are sandboxed and context isolated. Their limited page preload reports lifecycle protection signals; it exposes no privileged command API. Native window drag regions belong to trusted UI components, not web pages: page-defined `app-region` and `window-drag` styles cannot intercept input through another page.

A page that asks for HTTP basic auth (or a proxy that does) opens a small modal sign-in window over the window it belongs to: host, realm, username and password. Sign in answers the challenge; Cancel, Escape or closing the window shows the server's 401 page. A wrong password asks again. Nothing is saved or logged.

Read the [component and user guide](docs/components.html) for workflows, exact API examples and limitations.

## Run

```sh
npm install
npm start              # the first run downloads the Electron binary
npm test               # state logic, plain node --test
npm run app            # builds Skiff.app and dmg/zip files into dist/, run this on a Mac
```

## Releases

`npm run app` builds a macOS app into `dist/` (dmg and zip for arm64 and x64) with electron-builder; run it on a Mac. Without signing credentials in the environment it builds unsigned.

Every push to `main` that changes more than `site/`, `docs/`, Markdown or `.claude/` cuts a release: the release workflow runs the tests, bumps the `alpha` prerelease number in `package.json`, commits `Release <version>` to `main` with the tag `v<version>`, then signs and notarizes the app and uploads it to GitHub as a draft, then publishes it as a pre-release once every file is in. Runs queue one at a time; if `main` moved while a run was testing, that run releases nothing and the newer run releases both. Do not tag by hand. Installed apps check every pushed tag, so never leave a release tag as a draft: their update checks fail until it is published. It needs these repository secrets: `CSC_LINK` (the base64 Developer ID .p12), `CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID`; `GITHUB_TOKEN` is provided by Actions.

Installed apps (packaged, macOS) check the published releases at launch, every hour, and when the app gains focus if the last check is over an hour old. An update downloads in the background and installs when Skiff quits. When one is ready the user is told in four places: a macOS notification once per version ("Skiff <version> is ready", a click restarts into it), the Skiff menu ("Restart to Update to <version>", with "Check for Updates..." below it until then), an Update pill on the Buoy, and a "Restart to update" action in the Settings panel. All of them call `updates.install`, which runs the normal shutdown (stop agents, sync and components, flush `state.json`) once and then `autoUpdater.quitAndInstall()`, so Skiff relaunches into the new version. `updates.check` checks now. Both are refused where updates are unsupported (not packaged, or not macOS).

`state.update` (in `state.get` and the event stream, never saved to `state.json`) is `{status, version?, percent?}` with `status` one of `idle`, `checking`, `downloading` (with `percent`), `ready` (with `version`) or `error`; it is absent where updates are unsupported. A ready update stays `ready` through later checks and errors until it is installed. A prerelease version is only offered to apps already on a prerelease. Dependabot opens a pull request for each new Electron release, which is how Chromium security fixes reach users.

Skiff can be made the default browser from Settings, in the packaged app on macOS.

Data dir: `~/Library/Application Support/Skiff` on macOS, `~/.config/Skiff` elsewhere. Set `SKIFF_DATA` to use another one (the CLI honors it too).

| File | What |
| --- | --- |
| `state.json` | spaces, profiles, tabs, folders, archive, settings and window bounds |
| `shell/` | if present from an older profile, preserved and migrated to an owned `legacy.shell` component |
| `favicons/` | site icons saved by the core; tabs name them by a path relative to the shell |
| `api.json` | `{port, token}`, mode 0600, rewritten at each launch |
| `passwords.enc` | saved passwords encrypted with the operating system key store, mode 0600 |
| `components/` | composition, owned source, active revisions, recovery backups and versioned component data |
| `transcripts/` | normal-chat recovery records; not private chats |
| `sync/` | opt-in sync configuration and encrypted journal; not cookies or passwords |

A profile saved on another shell by an older version loses its `settings.shell` on load and opens in Layer.

## Interface

Skiff has one interface, Layer (`shells/layer/`, the bundled stock). Every tab is a window on a transparent desk over your screen, each with its own frame, and the Buoy, a small pill floating above the desk, is the way into everything else: it grows into a card with the command bar, favorites, a row of status chips with the space's tabs in one list, the space dots and Settings (see Desk shells below for how windows, the Buoy and exposé behave). The card has no space title row; the Buoy's pill names the space, and Settings and Archive show their own title. Text is set in the Allo variable font in three styles: friendly text, round display for titles and headings, and sharp tabular data (URLs, times, counts) with Allo's disambiguated I, l, 1 and 0. Agent commands and code stay in the system monospace. Allo is bundled locally as `assets/AlloVariable.woff2` in `shells/layer/` under the SIL Open Font License (`assets/Allo-OFL.txt`); the interface needs no font service.

Cmd+T opens the command bar: the Buoy grows into a card in the middle of the desk, over the live windows. Type and the top result fills in: `red` becomes `reddit.com` with the completed part selected, so Enter opens it in a new tab and Backspace removes the completion. Completions come from the hosts of open tabs, a built-in site table and the archive, in that order. Below the completion the bar lists open tabs from every space (Enter switches to one), sites from the table, up to three archived tabs (Enter reopens one), and a last row that opens the text as an address or searches it with the search engine chosen in Settings. Up and Down move the selection; Escape or a click outside closes the bar. Cmd+L opens the same bar with the current address selected; Enter then navigates the current tab instead of opening a new one.

Tab on a completed site, such as `youtube.com`, `maps.google.com`, `github.com` or `wikipedia.org`, turns the bar into a search of that site: a `Search YouTube` chip appears, you type the words, Enter opens that site's results page. Typing the host and a space does the same. Backspace on the empty box returns to the host. The sites and their search URLs are the `SITES` table in `shells/layer/common.js`; edit it to add your own.

Favorites belong to a space. Each space shows only its own favorites, as an icon row in the card above the space's name and as small icons in the Buoy. An icon shows the site icon and no text; the title is in its tooltip. A tab without an icon shows a globe in a favorite and a letter in a row.

Icons are files. The core saves the icon of each page you open under `favicons/` and keeps the path in `tab.favicon`. Imported tabs get the icon Arc already saved for them. At startup and after an import the core also fetches icons for tabs that still have none: one request for the page and one for its icon per site, from a separate in-memory session that sends no cookies. If the icon a page names cannot be used, `/favicon.ico` is tried once. A file that cannot be drawn shows the globe or the letter instead. Icon files are never deleted.

The card's footer holds the spaces as dots. Drag a space before or after another to reorder it. Arrow keys, Home and End move focus; Enter activates the focused space. Alt+Shift+Left/Right reorders it without changing the active space. Space order survives a restart.

Swipe two fingers sideways over the Buoy, the open card or a window's ear to switch spaces. About 30 pixels of travel is enough. One flick moves one space, however long its momentum runs, and stops at the ends. A new flick switches again at once, even while the last one is still coasting. The lists slide in briefly, unless the system asks for reduced motion. Vertical scrolling, pinch gestures, text inputs and open dialogs do not switch spaces. An overflowing space strip scrolls normally. Over a web page the swipe belongs to the page instead.

Swipe two fingers sideways on a web page to go back or forward, as in Chrome on the Mac: toward the right goes back, toward the left goes forward. A round arrow slides in from that edge and fills as you swipe; about 140 pixels of travel navigates, and reversing before that cancels. One swipe navigates once, however long its momentum runs, also into the page it opens. It only starts when nothing under the pointer can still scroll that way, so carousels, maps and wide tables scroll first, and never when the page handles the wheel itself, on a pinch, or when there is no history that way. The page keeps all its scrolling.

A tab opened from a page, such as a link that opens a new tab, appears indented under the tab it came from, while both are in the same section of the card. These trails can be any depth. Closing a tab lifts its children one level. Pinning a tab, making it a favorite or moving it to another space takes it out of its trail. Ctrl+Tab follows the order shown.

There are no pin or favorite buttons. The card has the bar's input with back, forward and reload at its right end (hidden while you type), the favorites row, a row of chips (Unread, Active, In progress, Done, Pinned, each with its count, and All on the far right), then one list: the open space's ordinary tabs in status order with no section heads, a small gap, then Pinned with its folders and the New tab row. A chip filters the list to that status (an empty one says so in a line); one chip is pressed at a time, All is the default, and the card opens on All every time. Every row of the open space starts with its status mark, drawn the same in its chip: a filled accent dot for Unread (the title is bold too), a ring for Active, a broken ring for In progress, a check for Done and a pin for Pinned. Each other space follows under a hairline and its own head (shown only under All, never filtered): its dot, name and tab count. Its group lists its favorites and pinned tabs that have a page loaded (never-opened ones are left out), then its ordinary tabs in status order, flat with no status heads or marks. Its rows only switch to that space and tab or close it, with no drag or move keys. A row ends with an agent's dot and "Agent state" (for example "Claude working") only when an agent is involved; the dot is a ring while it works and green when it is done. A Done row's tooltip tells when it archives. The eye and close buttons show on hover or focus, and on the current row. A tab producing sound shows a small speaker on its row, its favorite tile, the tab list and the Buoy's favorites (`tab.protections.audible`, from `audio-state-changed`). Drag any tab of the space into favorites or onto a chip to make it a favorite, pin it, or move it to that status, or between rows to take the status of the row it lands next to; In Progress and All take no drops. Drop on a folder name to add it to that folder, also when the folder is closed.

While you drag, the card shows what a release will do. A dashed copy of the tab sits where it will land, in the form it will take: an icon among favorites, a row in the list. The other items make room, and the original fades or hides so the tab never shows twice. Over a space dot or a chip, a caption names the target and the dot or chip is outlined. Where a release would change nothing, no copy appears and the cursor says so. Escape cancels. A screen reader hears the pending result. A trail child reorders only among its siblings.

With a tab focused, Alt+Shift+Up/Down reorders it within its status. At the edge of a status a top-level tab steps into the next one (never into In Progress), and back. Alt+Shift+Left/Right moves it to the adjacent space, which reloads it in that space's profile session when the profile differs. On a Mac, Alt is Option.

Cmd+Shift+N (Ctrl+Shift+N elsewhere) opens the incognito space and the command bar. There is one incognito space. It has a dark look, its own session and a close button in its title row. Nothing a site stores in it survives: its tabs are not in `state.json`, closing a tab does not archive it, its tabs move between buckets but are never archived, and its icons are held in memory. The session is the on-disk partition `incognito`, so uBlock Origin runs there; everything sites keep in it (cookies, cache, local storage, IndexedDB, service workers and the rest) is wiped when the space closes and at every start, and only the extension's own data stays. A crash that skips the wipe is caught at the next start. Tabs cannot move into or out of it. Normal spaces and settings are kept as usual.

Cmd+Shift+C (Ctrl+Shift+C elsewhere) copies the current tab's address and shows "Copied URL" on the Buoy for a moment. The page keeps focus. `tabs.copyUrl {id?}` does the same for any tab and returns `{url}`.

Browser keys work as in Chrome, with Ctrl in place of Cmd elsewhere. Cmd+Left and Cmd+Right (Alt+Left and Alt+Right on Linux and Windows) go back and forward; inside a text field the field keeps them. Cmd+Shift+R reloads without the cache. Cmd+Shift+] and Cmd+Shift+[ show the next and previous tab. Cmd+1 to Cmd+8 show that tab of the space, counted as Ctrl+Tab counts them, and Cmd+9 shows the last. Cmd+= (or Cmd+Plus), Cmd+- and Cmd+0 zoom the page in, out and back to 100%, as do Ctrl+wheel; a trackpad pinch magnifies the page as Chrome does on the Mac. Site zoom is remembered per profile and origin; private zoom is not persisted. Cmd+P prints the page. Cmd+S sends the shell `toggle-sidebar`, which Layer uses to open and close its Buoy card like Cmd+T. The View menu makes the interface larger, smaller or its actual size. `tabs.select {index}`, `tabs.zoom {id?, delta}`, `tabs.print {id?}` and `tabs.reload {id?, ignoreCache?}` are the commands behind them.

Cmd+Shift+U (Ctrl+Shift+U elsewhere) opens the panel of the first extension that has one, such as uBlock Origin's, over the page; it closes when it loses focus. See Extensions below.

The Settings button in the card's footer opens Settings, in place of the tab list. It has four pages, picked with the same chips as the tab list (arrow keys move across them) and each one a short list of one-line rows, the name on the left and its value or control on the right: **This space** (name, color, Delete this space), **Browsing** (search engine, auto-archive delay, tab layout), **Agents** (your AI agents, see Your agent) and **Skiff** (uBlock Origin's panel or dashboard, the update, default browser and logs rows, Import from Arc, Fill saved password). It opens on This space, or on Browsing in the incognito space, which has no space to rename or delete, and remembers nothing between openings. Descriptions are not printed; they are in each row's tooltip. The delay is how many hours a tab can go without being shown before it moves to Done; a Done tab is archived a day later (see Tab buckets). A delay of zero stops tabs moving to Done on their own. The search engine is Google by default; the list also offers DuckDuckGo, Bing, Brave Search, Kagi and Ecosia, and `settings.set {"searchUrl": "https://example.com/?q=%s"}` sets any other URL with `%s`, which the list then shows as Custom. Archive has its own button. Deleting a space and clearing the archive require confirmation. Deleting a space archives its favorites with its other tabs. Every default shortcut is available in every profile; saved entries override a default with the same accelerator (see below). `ui.emit {"name": "toggle-settings", "data": {"section": "agents"}}` opens Settings at its Agents page (it never closes it).

## Your agent

Ask your own AI agent from the command bar. Press Cmd+T (Ctrl+T elsewhere) and type: the bar offers **Ask <agent>** with the model and effort it will use. Text that reads like a question or a request is the first row, so Enter sends it: it ends in a question mark, starts with a word such as why, how, can or explain and has three words or more, mentions I, me, my, you, we or us, runs to eight words or more, or has five words or more with two common little words (the, of, to, and). Words to look for (`best pizza toronto`, `react useEffect cleanup`), an address and a single word search instead, and the agent waits at the bottom of the list. The reading is local and instant, never a network or model call.

Guessed wrong? For about 8 seconds after the bar opens a tab by searching the web or by asking the agent (not an address, not a site search), a small pill offers the other one: **Meant to ask Claude?** beside a search tab, **Meant to search Google?** beside a chat tab (the default agent, and the engine in Settings). It sits in the window's top edge right of its ear. A click closes that tab and does the other thing with the same words (`tabs.reroute`). The pill waits while the pointer is on it, fades out by itself, and goes at its x, when the tab navigates away, or at the first click in the tab's page (scrolling and hovering keep it). Tab on that row switches the bar to agent mode, where you pick the agent, the model and the effort, and can tick **Include this page**. Cmd+J (Ctrl+J elsewhere) opens the bar straight in agent mode, or switches an open bar to it and keeps what you typed. Backspace in an empty field leaves agent mode. Skiff speaks the [Agent Client Protocol](https://agentclientprotocol.com) (ACP), JSON-RPC over the agent's standard input and output, so any agent with ACP support works.

Each question opens a new chat tab, nested under the page you asked from, titled with your question and marked with a sparkle. Its loading bar runs while the agent works. The tab is a quiet reading view modelled on bb: one centred column, your messages in grey bubbles on the right (with the page they carried, if any), the agent's answers as plain text with headings, lists, bold, italics, inline code and code blocks (a link shows its address on hover and does not open), its thinking folded into a **Thought** row that opens on click, and each tool call as a row that shows whether it is waiting, running, done or failed. A permission request sits in a tray above the composer with the agent's own options. In the composer you type a follow-up (Enter sends, Shift+Enter starts a new line), switch the model or effort for the next answer from the two menus beside Send, or press Stop. The model and effort you last used become the defaults for the next question. Chat tabs close, archive and move like any other tab. After a restart a chat tab asks the agent to load its session again (ACP `session/load`) and rebuilds the conversation from it; an agent that cannot load sessions leaves the tab saying so, and the next message starts a fresh session. Chat tabs and the browser tools are set in Allo, bundled as `chat/AlloVariable.woff2` and `components/browser-tools/AlloVariable.woff2` under the SIL Open Font License (`Allo-OFL.txt` beside each); code in chat stays in the system monospace.

Agents live in **Settings > Agents**; the gear at the top of any chat tab opens it. Each agent is one row: a dot showing whether it is running, its name, **Default** or a **Make default** button that appears on hover, and, for the default agent, its model and effort. Click a row to open it in place: its command, the Skiff skill line, any error, **Remove**, and for the default agent the **Model** and **Effort** menus that set what it uses for the next question (Skiff starts the default agent while Settings is open so it can list them). The last row, **Add agent**, opens the add form in place: pick a command from the list (or type your own, which the list then shows as Custom), check the name and press **Add agent** or Enter. The list starts folded. With no agent set up, the bar's row reads **Ask an agent** and Enter opens Settings at Agents with the add form open, as does **Add an agent...** in agent mode. A question that reached a chat tab before any agent existed (`ai.ask` from the API) waits there with **Connect an agent**, which opens the same place, and goes to the first agent you add. `settings.set {"ai": {"agents": [{"name": "omp", "command": "omp acp"}]}}` sets the whole list from the API, and `agent`, `model` and `effort` in the same object set the defaults. Commands for example:

```sh
omp acp
ssh myserver omp acp
gemini --acp
npx -y @agentclientprotocol/codex-acp           # Codex
npx -y @agentclientprotocol/claude-agent-acp    # Claude
hermes acp
```

Each agent runs once, in your login shell with its own credentials, in a working folder `ai/` in the data dir, and serves its chats. Agent mode or Cmd+J starts it so the bar can list models and efforts; no question is sent until you submit it. **Include this page** explicitly sends the page's title, address, selection and bounded text. There is no automatic AI capture. Browser tools require a separate explicit grant in Browser Tools > Grants: select tabs or spaces, read/mutation rights and any optional component tools. Grants can be revoked. ACP permission cards are the agent's own requests, not a replacement for Skiff's scope checks. Remote agents need their own secure route to this machine's loopback tools.

A **Machine** pill (in the chat composer and in agent mode of the bar, beside model and effort) picks where the agent runs: **This Mac**, or another machine from `bb machine list --json` (run in your login shell; the pill is hidden when bb is missing or lists no other machine, and a machine that is not connected is marked). A chat on another machine runs its agent over ssh as `ssh -T -o BatchMode=yes -o ServerAliveInterval=30 <alias> ...`, in that machine's login shell from its home folder, where the alias is the machine's bb name lowercased with each run of other characters turned into `-` (`Latitude` is `latitude`, `Personal macbook` is `personal-macbook`), so it must be a host in `~/.ssh/config` (or resolvable) that logs in without a password prompt; an unknown host or refused login shows ssh's own message in the chat. The same agent can run here and on other machines at once, and a chat remembers its machine across restarts. Changing a chat's machine after it has turns starts a fresh session there (earlier turns stay in the tab but are not sent). The last pick is the default for the next question (`settings.ai.machine`). A remote agent works in the remote home folder and gets no Skiff browser tools or grants, since the app's tool server listens on this Mac only; the Skiff skill in Settings stays about this Mac's harness.

Read and Mutate are independent grant choices, not a bundled permission. Creating a grant does not automatically select or merge it: use **Use for agent** or `grants.select {id, sessionId?}`. Component customization is a separate exact-ID `components` scope, distinct from callable `tools`. **Customize this** confirms the selected component, creates an owned copy when needed and starts an agent chat without page inclusion. The agent can inspect, edit, check and preview only authorized source; apply, enable and revert still require native approval of the exact revision. Revocation never silently falls back to a broader grant.

With a Mutate grant the agent can use the page, not only read it: it takes a snapshot of what can be clicked, clicks, types, presses keys, scrolls, takes a screenshot and waits for text, in tabs it opened or you handed to it, and nowhere else. The work is visible: the tab is marked with the agent's name and a purple dot, a purple bar over it says who is using it and offers **Take over**, and an agent's cursor glides to each target before it clicks. You can take the tab at any moment, and the agent is told to stop. When an agent asks for a tab of yours, you answer **Allow** or **Deny**. Nothing the agent does moves your keyboard, your mouse or the focus of any other tab or app. The commands and the rules are under API.

An agent you start elsewhere (Claude Code, omp, Codex, Gemini CLI or Hermes in a terminal) knows nothing about Skiff. When you add an agent in Settings > Agents, the box **Teach it to use Skiff** (checked by default, hidden when Skiff cannot tell the harness from the command, as for any `ssh` command) installs a skill into that harness's own user skills folder, and each agent's row shows **Skiff skill installed**, **Update Skiff skill** or **Install Skiff skill**. The skill is `agent-skill/skiff/SKILL.md`, a copy of which goes to `~/.claude/skills/skiff/` (Claude Code), `~/.omp/agent/skills/skiff/` (omp), `~/.agents/skills/skiff/` (Codex), `~/.gemini/skills/skiff/` (Gemini CLI) or `~/.hermes/skills/skiff/` (Hermes), each from that harness's own documentation. Skiff writes only under your home folder, atomically with mode 0644, and only where the file is missing or still an exact copy of a Skiff version listed in `agent-skill/versions.json`: a file you edited is never overwritten (the row says so), and a skills folder that is a symlink out of your home is refused. The skill reaches Skiff with `curl` to `/rpc`, reading `port` and `token` from `api.json` with `sed` and keeping the token out of its output, not through `bin/skiff`: in the packaged Mac app that script sits inside `app.asar`, which a system Node cannot run. A program that can read `api.json` has the owner API, as any program running as you does (see API); that is what the skill gives the agent. When you change `SKILL.md`, append its new sha256 to `agent-skill/versions.json` (a test fails until you do), so that copies of the old text count as outdated, not edited.

Incognito pages cannot be included or accessed by browser tools. Private chats are not stored in Skiff's local transcripts, though an external agent may retain its own record. Local recovery transcripts for normal chats are opt-in through `transcriptRecovery`, with configurable retention; saved transcripts can be searched, exported and deleted. If ACP cannot restore a session, a saved local transcript is read-only recovery, not hidden replay: starting a fresh session does not send the recovered conversation. Agent credentials remain the agent's responsibility. Quitting stops managed agent processes.

## API

Every command goes through one registry. Ask the running app what exists:

```sh
bin/skiff commands.list
bin/skiff state.get
bin/skiff tabs.create '{"url":"example.com"}'
bin/skiff tabs.create '{"url":"how to row a skiff","activate":false}'
bin/skiff tabs.create '{"url":"example.com/docs","parentId":"<tab-id>"}'
bin/skiff tabs.setFavorite '{"favorite":true}'
bin/skiff tabs.setPinned '{"pinned":true,"folder":"Docs"}'
bin/skiff tabs.setBucket '{"bucket":"done"}'
bin/skiff ui.emit '{"name":"import-arc"}'
bin/skiff ui.emit '{"name":"toggle-settings"}'
bin/skiff spaces.move '{"id":"<space-id>","index":0}'
bin/skiff import.arc.preview
bin/skiff passwords.fill
bin/skiff incognito.open
bin/skiff archive.restore
bin/skiff events            # server-sent events, one full state per change
```

Where `id` is optional it means the active tab. Tabs open only `http:` and `https:` URLs. Other text becomes a search.

A tab is plain, pinned or a favorite, and always belongs to one space (`tab.spaceId`). A favorite shows only in its space; `tabs.setFavorite` keeps the tab where it is. Favorites, pinned tabs and tabs in progress never move to Done by themselves. Folders are persisted entities with `folderId` and optional `parentId`: nested and empty folders survive, and `folders.setCollapsed` controls their presentation. Trails can be collapsed independently.

Tab buckets: every tab, web page or chat, is in exactly one bucket of its space, shown in this order: `favorites`, `unread`, `active`, `progress`, `later`, `done`. `favorites` is `tab.favorite` and `later` is `tab.pinned` (with its folder); every other tab has `tab.status`, one of `progress`, `unread`, `active` or `done`, plus `tab.doneAt` (milliseconds) while done. Both are saved; a saved tab with no status is `active`, a saved `progress` tab becomes `active` on start, and a favorite or pinned tab has no status. Every tab in `state.get` carries a computed `bucket` and `browser_list_tabs` lists it for each tab. Tabs move between buckets by themselves:

| Event | From | To |
| --- | --- | --- |
| `tabs.create`, a link opened from a page, an extension, or `archive.restore` of a web page | none | `progress` |
| a page's main frame stops loading | `progress` | `active` if it is the active tab and Skiff is in front, else `unread` |
| a progress page that never started loading (checked by `archive.sweep`) | `progress` | `unread` |
| a tab is shown (`tabs.activate`, a switch of space or tab, or Skiff coming to the front with it shown) | `unread` or `done` | `active` |
| a chat starts a turn or restores its session | `active`, `unread` or `done` | `progress` |
| a chat turn ends, or the agent asks permission | `progress` | `active` if it is the shown tab and Skiff is in front, else `unread` |
| `archive.sweep`: not shown for `autoArchiveHours` hours (not the active tab, a split tab or a tab in `progress`) | `active` or `unread` | `done`, with `doneAt` |
| `archive.sweep`: 24 hours after `doneAt` | `done` | the archive (never for the incognito space) |
| `tabs.setFavorite {favorite: false}` or `tabs.setPinned {pinned: false}` on a favorite or pinned tab | `favorites` or `later` | `active` |

Reloading a page, navigating inside it or to a new address, and a chat that is idle never move a tab. A tab of the incognito space follows the same rules in memory and is never written or archived. `tabs.setBucket {id?, bucket}` moves a tab by hand: `favorites` makes it a favorite, `later` pins it (folder cleared), and `active`, `unread` or `done` clear its favorite and pin and set the status (`doneAt` for `done`); a tab already in that bucket stays as it is. `progress` cannot be set by hand and is refused with `bad_params`, like an unknown bucket and an agent tab. `archive.sweep` returns `{archived, done, settled}`, the ids it archived, moved to Done and settled. Layer's card draws the buckets as sections (see Desk shells).

A plain tab may have a `parentId`, the plain tab of the same space it was opened from. `tabs.create {parentId?}` sets it; a parent that is pinned, a favorite or in another space is ignored. `tabs.move` reorders a tab among the tabs with the same parent. `tabs.move {id, spaceId}` moves a tab to another space as a root and gives it that space's profile (`sessionPartition`, `profileId`; the incognito space stays closed to it). When the profile differs, the page is recreated and loads its current address in the new profile's session, and a tab-level `browserIdentity` is dropped so the new profile's default applies (a WhatsApp tab stays `compatible`); within one profile the live page is untouched. A link peek (`userPeek`) takes `spaceId` only, its own space included, and becomes an active tab there like `peek.promote`. The page's right-click menu has Move to Space listing the spaces the move allows; it runs `tabs.move` then `tabs.activate`, so the page stays in front.

`tabs.create {intent: true}` and `ai.ask {intent: true}`, which the command bar passes, make the new tab remember how it was opened (`tab.intent: {text, sent: 'search' | 'ask', at}`, in memory only, never saved, dropped when the tab navigates); `tabs.reroute {id}` closes such a tab and, in the same space, asks the default agent with the same text (for a search tab) or searches `settings.searchUrl` with it (for a chat tab, whose running turn is stopped), even if the text looks like an address. It is refused for a tab with no `tab.intent`.

`tabs.close` returns `{archived: id}` for a plain tab, `{unloaded: id}` for a pinned tab or a favorite, which stays in the card, and `{closed: id}` in the incognito space, where the tab is dropped and not archived.

`incognito.open` creates the incognito space if needed, switches to it and returns it. The space has `incognito: true`. `spaces.remove` closes it and wipes its site data (see Interface). `state.get` and the event stream include it while it is open; `state.json` never does.

An agent working beside you opens its own tabs with `tabs.create {url, agent, spaceId?}`, where `agent` names it (at most 40 characters). An agent tab is an ordinary tab: it is in `state.tabs` and in its space's tab list (in a desk shell it is a hidden window on the desk until you show it), it uses the session of its space (the active space by default, or the first normal one while the incognito space is active), so it shares that space's cookies and sign-ins, and the incognito space is refused with `bad_params`. It never takes focus and never becomes the active tab by itself. It is saved in `state.json` like any tab, with its agent's name: after a restart it is back, still marked with the agent, `idle`, with no lock, and its page loads when it is shown or the agent drives it. Besides the tab's fields it carries `agent` (the agent that may drive it), `agentState` (`working`, `idle` or `done`), `agentControl` (`agent` or `user`), `agentUnseen: true` while a finished tab has not been looked at, `agentSummary` and `agentRequest {agent}` while an agent is asking for it; only `agent` is saved. Layer marks it with the agent's name and a purple dot. A link it opens in a new tab becomes another tab of the same agent. `tabs.navigate`, `back`, `forward`, `reload`, `zoom`, `print` and `copyUrl` work on it by id, `tabs.read {id?}` returns its `{title, url, selection, text}`, `tabs.activate {id}` shows it like any tab, and `tabs.close` archives it like any tab (`{archived: id}`): restoring it from the archive gives a plain tab, and the agent has to be handed it again. `tabs.move`, `tabs.setFavorite`, `tabs.setPinned` and auto-archive treat it like any tab, except that auto-archive leaves it alone while it is working.

```sh
bin/skiff tabs.create '{"url":"example.com","agent":"bb"}'
bin/skiff tabs.snapshot '{"tabId":"<tab-id>","agent":"bb"}'
bin/skiff tabs.type '{"tabId":"<tab-id>","agent":"bb","ref":"e3","text":"select 1"}'
bin/skiff tabs.click '{"tabId":"<tab-id>","agent":"bb","ref":"e1"}'
bin/skiff tabs.screenshot '{"tabId":"<tab-id>","agent":"bb"}' | jq -r .data | base64 -d > agent.jpg
bin/skiff agent.finish '{"tabId":"<tab-id>","agent":"bb","summary":"ran the query"}'
```

An agent drives a tab with these commands, which are also MCP tools (`browser_snapshot`, `browser_click`, `browser_type`, `browser_press`, `browser_scroll`, `browser_screenshot`, `browser_wait`, `browser_request_tab`, `browser_finish`) and need a mutation grant like `browser_navigate`. Every call names its `agent` and a `tabId` (a scoped grant always acts as its own agent, named by its owner, and its schema leaves `agent` out). `tabs.snapshot` returns the page as an outline of its interactive elements, one line each, `e12 button "Run Query" [disabled]`, plus its headings, from the accessibility tree (`Accessibility.getFullAXTree`), at most 300 elements and about 24,000 characters; the refs last until the next snapshot. `tabs.click {ref | x, y}` sends real mouse events (move, press, release) to that page, `tabs.type {ref?, text, clear?}` focuses the ref and inserts the text whole (`Input.insertText`, so autocomplete cannot rewrite it; `clear` selects and deletes what was there first), `tabs.press {key}` presses a key or shortcut such as `Enter`, `Tab`, `ArrowDown`, `F5`, `Shift+Tab` or `Meta+Enter` (`CmdOrCtrl` is Meta on a Mac), `tabs.scroll {dx?, dy?, ref?, x?, y?}` wheels the page and returns its scroll position, `tabs.screenshot` returns `{mime, width, height, data}`, a JPEG of the viewport at most 1280 pixels wide with base64 `data` (an image block over MCP), and `tabs.wait {text | url, timeout?}` polls until the page text or its address contains the string, 10 seconds by default and 60 at most, and fails with `timeout`. Input goes through the tab's own DevTools channel (`webContents.debugger`, attached on the first call, released by `agent.finish` and when the tab closes) with focus emulation, so a background tab acts focused and nothing ever touches the operating system's focus, mouse or keyboard. Only one debugger can attach: while DevTools is open on the tab, calls fail with `devtools_attached`. The screenshot is Electron's own capture, because DevTools' waits forever for a frame from a page parked in the hidden window.

The rule is in the commands themselves, for the owner CLI and `/rpc` as much as for scoped grants: an agent may drive only a tab it opened with `tabs.create {agent}` or one it was handed, and a call on any other tab fails with `forbidden`, a missing `agent` with `bad_params`. `tabs.handToAgent {id, agent}` hands any web tab of a normal space to an agent (it starts `idle`, and is saved with the agent like any agent tab). An agent asks for a tab with `agent.requestTab {id, agent}`: the tab shows a strip, "bb wants to use this tab", with Allow and Deny, and the call resolves `{allowed, agent}` once it is answered, which `agent.answerTab {id, allow}` does for the buttons. A request ends when it is answered, the tab closes or the agent's call is dropped; a tab the agent already has answers `{allowed: true}` at once. A scoped grant's `tabs.create` always opens its agent's own tab, so a Skiff chat can drive what it opens.

While an agent works in a tab (`agentState: "working"`, from its creation or its first call), a control layer covers the page: a transparent view of its own over that tab (not the shared overlay), which draws the agent's cursor gliding to each target before a click lands, a ripple, a highlight on the field being typed into, a purple rim and a bar, "bb is using this tab", with **Take over**. It swallows your mouse on that tab, and your keys to the page are dropped in its `before-input-event`; other tabs and windows work as usual. DevTools key and mouse events are reported to `before-input-event` and `before-mouse-event` just like yours, so the page tells its agent's from yours by what the agent is sending at that moment. **Take over** (`agent.takeOver {id}`) hands the tab to you: the layer shrinks to a strip with **Give back** (`agent.giveBack {id}`), and the agent's next call fails with `user_has_control` and a message telling it to stop. The layer is also only a strip while an agent's request waits. A tab that is `idle` or `done` has no layer, and the agent's next call makes it `working` again.

`agentState` is `working` after a call (or on creation), `idle` once two minutes pass with no call (checked every 5 seconds; `SKIFF_AGENT_IDLE_MS` shortens it for tests), and `done` after `agent.finish {tabId, agent, summary?}` (the summary is one line of at most 200 characters), which also sets `agentUnseen` unless the tab is the one you are looking at. A Skiff chat finishes every tab its agent opened or drove when its turn ends. `agentUnseen` clears when the tab is shown (`tabs.activate`, `desk.show`, or a switch that shows it), and the next agent call clears it too. Layer's Buoy lists the agent tabs that are working, idle, asking or finished and unseen, and shows a red dot while any is unseen or asking.

When an agent tab is not on screen, Skiff keeps it in one hidden `BrowserWindow` that it creates with the first such tab and closes with the last: never shown, not focusable, out of the taskbar, 1280 by 800, painting while hidden. These pages are not throttled in the background, so their timers run at full rate and `document.visibilityState` is `visible`. On Linux under Xvfb, with no debugger attached, a page that has never been in a visible window gets no frames at all there: `requestAnimationFrame` never fires and `capturePage` fails with "Current display surface not available for capture". Showing the hidden window off-screen does not help. So each time an agent page is ready (`dom-ready`), and before each screenshot, Skiff adds its view to your window at 1 by 1 pixel and takes it out again in the same tick, which never paints and does not move the keyboard; from then on the page renders in the hidden window and `capturePage` returns its real pixels at 1280 by 800. Because nothing draws the hidden window, a page that keeps repainting gets about one animation frame a second there (a page that does not repaint gets 60), and full speed again while shown. Playwright's debugger connection hides all of this, which is why `e2e/agent-tabs.spec.js` checks it on a second Skiff with nothing attached. macOS has not been checked. Because the hidden window exists, closing your window quits Skiff on Linux and Windows instead of waiting for `window-all-closed`.

Open **Settings → Import from Arc** to choose any number of Arc profiles, the categories to bring over, and whether to keep their spaces. All profiles start selected; use the checkboxes or Select all / Clear selection. Saved passwords and website sign-ins start unchecked. Review your selection before importing; one native confirmation, with Cancel selected, covers all selected profiles before Skiff opens protected databases or asks Keychain for Arc's Safe Storage key. Preview reads profile metadata and sidebar contents only.

The flow follows [Yab's local import approach](https://yetanotherbrowser.com/manual/bring-in): no upload or plaintext export. Arc can stay open; SQLite reads include committed WAL records. Each imported profile gets an isolated browser session, including its favorites, so accounts from different profiles do not overwrite each other. Arc shows a profile's favorites in all of its spaces; Skiff puts them in the first space imported for that profile. New tabs in an imported space use that profile. Moving an existing tab or making it a favorite preserves its original session.

For the API, call `import.arc.preview`, then `import.arc` with `profileIds` (a nonempty array of returned IDs), `categories: {tabs, openTabs, passwords, logins}` (all booleans), and `keepSpaces` (boolean). Every ID is validated before import; repeated IDs are processed once. `tabs` includes favorites, pinned tabs and folders. With `keepSpaces: false`, each profile's tabs collect in a separate new space. Password-only or sign-in-only imports also create a profile space so the imported data is usable. The API cannot bypass the native confirmation, and no command returns passwords or cookies.

Results include totals and expandable per-profile counts. Profiles with warnings open automatically. Passwords and sign-in cookies report imported, skipped and failed counts separately. A failed profile does not stop the others; unreadable database counts are unknown and reported as warnings. Repeat imports preserve existing passwords and destination cookies. Arc source IDs prevent duplicate tabs after renaming spaces, navigating tabs or changing the layout option. Layout choices apply to new imports and do not rearrange existing tabs. The API returns each profile's counts and warnings in its `profiles` array.

Keeping Arc spaces also imports their background colors. Modern blended gradients retain their base and overlay stops, alpha and intensity, with light/dark semantic backgrounds. Legacy shaded palettes become solid backgrounds. Choosing a space color in Settings or `spaces.update` replaces the imported background, including when choosing the same accent; renaming does not. Repeat imports keep existing backgrounds and manual overrides. Combined profile spaces (`keepSpaces: false`) have no single source theme and retain the default appearance.

Older imports can backfill a missing background only when the Arc source space ID and profile partition match and the current accent still exactly matches Arc's source accent. Name-only matches, different accents and explicit overrides are never backfilled. Old versions did not record color edit history, so an old edit back to the exact source accent is indistinguishable from an untouched import. Once changed with this version, an override remains protected across restarts and imports.

To use an imported password, open the site's sign-in page in the imported profile and choose **Settings → Fill saved password**. The native account picker identifies the exact site; filling never submits the form. Only exact HTTPS origins match. Skiff does not fill embedded frames, password-creation forms, ambiguous forms with multiple password fields, or forms that submit to another origin. Passwords remain encrypted at rest, outside browser state and API events.

Protected import currently supports macOS Arc v10 encryption and cookie database versions through 24. Unsupported encryption, partitioned cookies and unsafe records are reported rather than weakened. HTTP passwords, passkeys and site local storage do not transfer. Some sites will require signing in again. Source files are not modified; Skiff does not remove a password export because it does not create one.

Imported tabs stay asleep. Their icons come from Arc's own saved icons first: the `Favicons` database in each Arc profile folder, which is not encrypted and needs no Keychain. Skiff takes the icon Arc saved for the exact page, or else the newest icon Arc has for the same site. A running Arc keeps that database locked, so Skiff then reads a private temporary copy and deletes it. A missing or unreadable icon database is skipped without an error. Importing again also refreshes the icons of tabs from an earlier import. A site Arc had no icon for is asked once after the import, without sign-ins: those requests carry no cookies or other credentials and do not use the imported sessions. Tabs with no icon from either source keep a letter or a globe.

Automated checks cover synthetic encrypted SQLite databases, batch consent denial, profile isolation, repeat imports, partial failures and vault failures. Electron smoke runs on Linux and macOS verified signed-in HTTPS requests and approved password filling. Mac checks covered actual Keychain retrieval with a temporary synthetic key and a three-profile import with separate credentials and sessions for the same site. Real Arc credentials were not accessed.

Over HTTP, read `port` and `token` from `api.json`:

```sh
curl -s -X POST http://127.0.0.1:$PORT/rpc \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"method":"spaces.create","params":{"name":"Work","color":"#2f9e5b"}}'
# {"ok":true,"result":{...}}  or  {"ok":false,"error":{"code":"bad_params","message":"..."}}

curl -s -N http://127.0.0.1:$PORT/events -H "Authorization: Bearer $TOKEN"
```

Error codes: `unknown_method`, `bad_params`, `not_found`, plus `unauthorized` and `forbidden` at the HTTP layer and `internal` for bugs. A request is refused if it has no bearer token, carries an `Origin` header, or has a `Host` other than `127.0.0.1:<port>` or `localhost:<port>`. Bodies are capped at 1 MB. Do not send an `Origin` header from your client.

Command families include spaces, tabs, folders, profiles, link routing, split, peek, history, downloads, site permissions, find, reader, settings, components, grants, transcripts and sync, alongside desk, archive, import, passwords, extensions, AI and UI. `commands.list` returns the current descriptions and input schemas; `settings.catalog` describes editable settings. Each core entry carries what an interface needs to draw it: `title`, `description`, `type` (`boolean`, `number`, `integer`, `string`, or `action`), the current `value` (a string or number setting with an `enum` is a choice among those values), and for an action `actionLabel`, `status` (host-computed text, possibly empty) and `available`. An action has no value: `settings.run {id}` runs it and returns the refreshed entry. An action this platform or build cannot run is left out of the catalog. Entries with `quickPanel: true` are the ones an interface's quick Settings panel draws; `settings.catalog {quickPanel: true, owner: "core"}` lists them. Changing a value uses `settings.set`.

`spaces.move {id, index}` takes a zero-based integer position, clamped to the space list. It changes order only, preserving the active space, tabs and profile sessions.

`tabs.thumbnails {ids, width?}` returns `[{id, image}]` for up to 24 tabs in the order asked: `image` is a JPEG data URL of the page as it is on screen now, at most `width` pixels wide (480 by default, 3840 at most; a page narrower on screen keeps its own size), or null for a tab that is not on screen (hidden, in another space, not loaded) or cannot be captured. Layer's exposé draws its cards with it, one call per card at twice the pixels the card settles at, since the core encodes them one after another.

The agent is `ai.*`. `ai.agents` lists the configured agents with their status, models and efforts; `ai.warm {agent, machine?}` starts one and resolves once its models and efforts are known. `ai.machines {refresh?}` lists the machines an agent can run on (`{id, name, status, local, alias}`, this Mac first with id `''`), and `ai.agents` lists only this machine's agents. `ai.ask {text, agent?, model?, effort?, machine?, includePage?, tabId?, intent?}` opens a chat tab under `tabId` (the active tab by default) and returns `{tabId, chatId}` at once; with no agent configured the tab waits in setup with the text and sends it to the first agent added. A chat tab's URL is `skiff://chat/<chatId>` and its `chat` field holds `{agent, machine?, sessionId}`. `ai.chat {chatId}` returns the conversation (`status` setup, restoring, ready, running or error, `error`, `pending`, `sessionId`, `models`, `model`, `efforts`, `effort`, `permission {id, title, options}` and `turns`), restoring it with `session/load` if this run has not seen it yet. `ai.prompt {chatId, text}` sends a follow-up and returns `{turnId}` at once, `ai.configure {chatId, model?, effort?, machine?}` changes the model or effort for the next turn (a new `machine` starts a fresh session there), `ai.cancel {chatId}` stops the turn, and `ai.permit {chatId, optionId}` or `{chatId, cancel: true}` answers a permission request. A change to the agent list pushes `ai-agents` to the shell pages and chat tabs; a change to a chat pushes `chat` to that chat's own tab. `/events` streams both as `event: ai-agents` and `event: chat`.

Each `ai.agents` entry also carries `skill {harness, status, path}`, the Skiff skill in that agent's own harness: `harness` is `claude`, `omp`, `codex`, `gemini` or `hermes`, found from the command (a program on its own, or through `npx`, `bunx`, `pnpx`, `pnpm dlx` or `npm exec`; `env` and `NAME=value` prefixes are skipped), and `status` is `missing`, `installed`, `outdated` (an exact copy of an older Skiff version), `modified` (anything else, a symlink included), `error` (with `error`) or `unsupported` (an `ssh` command, a container, an unknown program; `harness` and `path` are null). `ai.installSkill {agent}` writes the skill for a `missing` or `outdated` one and returns `{agent, harness, status, path, written}`; it leaves `installed` and `modified` copies as they are (`written: false`), refuses a skills folder that leads outside the home folder, and pushes `ai-agents`. `ai.skillStatus {command}` returns the same `{harness, status, path}` for any command, configured or not, which is how the add-agent form decides whether to show its box.

`POST /mcp` is an MCP server with browser tools and explicitly tool-enabled component commands. The owner token from `api.json` is a powerful local credential; do not hand it to an ACP agent. Skiff instead derives scoped session credentials from explicit grants. Those credentials work only on `POST /mcp`, not owner `/rpc` or `/events`, and never authorize incognito access. Revocation also invalidates derived session grants. Component tools must be selected explicitly; their nested browser calls retain the originating grant's scope.

Shortcuts live in `settings.shortcuts` as `{ "<Electron accelerator>": { "method": "...", "params": {...} } }`. `settings.set {"shortcuts": {...}}` replaces the whole map and rebuilds the menu. Electron ignores an accelerator it cannot parse.

On load, any default accelerator missing from the saved map is added back, so a profile created before a default existed still gets it. To turn a default off, map its accelerator to another command.

System-wide shortcuts live in `settings.globalShortcuts`, the same shape, registered with Electron's `globalShortcut` so they fire while another app is in front. The handler brings Skiff to the front (restoring a minimized or hidden window, opening one if none is open) and then runs the method. The default `Alt+Space` (Option+Space on a Mac) opens the command palette like `CmdOrCtrl+T`; it takes the key from every app, so Option+Space no longer types a non-breaking space anywhere. `settings.set {"globalShortcuts": {...}}` replaces the whole map and re-registers it; missing defaults are added back on load as for `shortcuts`. An accelerator another app already holds is logged and skipped.

Browser identity has a profile default and an optional per-tab override. The profile default is selected with `settings.set {"browserIdentity": {"persist:main": "native"}}`; read `state.get` first because each tab's `sessionPartition` identifies its profile; moving a tab to a space on another profile changes it. Ordinary spaces share `persist:main`; imported Arc profiles have separate `persist:arc-...` partitions. Keys must start with `persist:` followed by letters, digits, dots, underscores or hyphens. Values are `native` or `compatible`; updates merge into the saved map and apply after restarting Skiff. Incognito partitions are not accepted.

`compatible` remains the default profile identity: Skiff removes its own and Electron's product tokens. `native` keeps the installed Skiff/Electron identity. Existing profile sessions, cookies and site storage do not move or clear.

New tabs opened at the exact host `web.whatsapp.com`, and older saved tabs restored at that host, get a persisted `compatible` tab override. A tab keeps its override when it navigates elsewhere, reloads, follows redirects or uses history. Popups choose independently by destination: a WhatsApp popup is compatible; an ordinary popup uses its profile default. Other tabs in a native profile, including Google tabs, remain native.

To choose an identity while navigating an existing tab, pass it to `tabs.navigate`, for example `tabs.navigate {"url":"https://web.whatsapp.com/","browserIdentity":"compatible"}` for the active tab. This recreates that tab's view with the same session before loading the requested URL; the new view starts a fresh navigation history. Omit `browserIdentity` to keep the tab's current choice, or pass `null` to persistently use the profile default, including on WhatsApp. Do not first navigate a native tab to WhatsApp and expect automatic site-only switching. A compatible tab stays compatible on Google; use a native tab or explicitly select `native` when navigating to Google.

Browser Tools > Profiles creates and names isolated profiles, assigns the profile for future tabs in a space, and manages external-link routing. A tab moved to a space on another profile joins that profile's session; existing tabs keep their session when a space changes profile. Browser identity remains an API setting rather than a dedicated identity editor.

## Logs

Skiff writes verbose JSON Lines to `~/Library/Logs/Skiff/skiff.log` on macOS, or to `<SKIFF_DATA>/logs/skiff.log` when `SKIFF_DATA` is set. Each line is `{t, lvl, scope, msg, ...data}`. The main process logs every command (`cmd`), webContents events (`wc`, including every page's console output and uncaught page errors), shell and overlay errors with stacks (`renderer`), app, window and tab lifecycle (`app`, `window`, `tab`) and the subsystems (`updates`, `extensions`, `ai`, `acp`, `sync`, `importer`, `http-auth`, `downloads`, `permissions`).

The level is `debug` by default. `SKIFF_LOG_LEVEL` (`trace`, `debug`, `info`, `warn`, `error`) changes it; `trace` holds high-frequency events and is off unless you ask for it. The file rotates at 20 MB, keeping `skiff.log` and `skiff.1.log` to `skiff.4.log`. Keys named like `password`, `token`, `secret`, `cookie`, `authorization`, `credential`, `otp` or ending in `key` are written as `[redacted]`, and strings are cut at 2 KB.

```sh
bin/skiff logs.path                                              # where the log file is
bin/skiff logs.tail '{"lines":200,"level":"warn"}'               # lines, level, scope, grep, since (30s, 10m, 2h, 1d or a date)
bin/skiff logs.tail '{"scope":"cmd","grep":"tabs.create","since":"10m"}'
bin/skiff logs.mark '{"note":"before repro"}'                    # a MARK line to bracket a repro
```

Settings has a **Reveal logs** action that opens the folder in Finder. To read the logs of the Mac enrolled in bb from another machine:

```sh
scripts/mac.sh logs 3000 'error|warn'   # last 3000 lines, case-insensitive extended regex (grep is optional)
scripts/mac.sh logs-fetch ./skiff-logs  # whole skiff.log into ./skiff-logs/skiff.log (last 1.2 MB gzipped at most)
```

## Customizing the shell

```sh
bin/skiff ui.shellPath      # {path, owner, readOnly} for the selected source
bin/skiff ui.capture '{"target":"shell"}' | jq -r .png | base64 -d > shell.png
bin/skiff ui.devtools '{"target":"shell"}'
bin/skiff ui.resetShell     # rebinds stock and legacy roles to the bundled Layer; backs up old data/shell if present
```

A `shell` capture shows the interface without the native webpage view; capture `page` for the page itself. Use Components to inspect selected source, copy it to an owned package, edit, check, preview and explicitly apply it. Stock source stays bundled and read-only; owned source edits do not activate a revision until applied. Older data-dir shell files migrate to a backed-up `legacy.shell` package and remain selected on migration. Chat has a stock `chat/chat.html` surface and can be independently bound like the launcher, frame and other roles.

Recovery: if an owned or legacy shell stops working, start Skiff with `--safe-mode`, run `ui.safeMode`, or pick Recovery > Use Safe Mode in the menu. Safe mode ignores every user component and your edited copy of the shell and loads the bundled Layer from `shells/layer/`, still as a desk window, without closing open pages. It lasts until Skiff restarts without the flag; nothing on disk changes.

Components can declare scalar settings in their manifests. Shared Settings resolves their defaults, global overrides and optional normal-space overrides, showing the owning component and the source of each effective value. Use `components.settings.list/get/set/reset` rather than a second settings file. Properties live outside source files; apply carries compatible overrides, while revert restores the previous code and its saved configuration. Versioned component data is not rolled back. Private-space persistence is rejected.

Every component UI, stock or owned, uses the same capability-checked bridge. Bundled management surfaces explicitly declare `host.manage` alongside call/event capabilities. A copied manager requires normal native approval; `call:*` alone is not administrative authority. Treat `host.manage` as powerful local browser administration, not an OS sandbox. Scoped agent invocations remain constrained by their original grant even through a management component.

The contract a shell must keep (the bundled Layer keeps it, and so must your owned copy of it):

- `window.skiff.call(method, params)` returns a promise of the result, or rejects with `{code, message}`.
- `window.skiff.on(name, listener)` subscribes to `state` (the full state after every change), `ai-agents` (the agent list, as `ai.agents` returns it) and to custom events sent with `ui.emit {name, data}`. Layer listens for `new-tab` (opens the command bar for a new tab), `focus-address` (opens it to edit the current address), `toggle-archive`, `toggle-settings`, `toggle-agents`, `ask-agent` (Cmd+J, opens the command bar in agent mode) and `import-arc`.
- Tell the core where the page goes: `skiff.call('ui.setPageBounds', {x, y, width, height, radius})` in CSS pixels, on load and whenever that rectangle moves. Nothing is shown until you do.
- Use `ui.setPageVisible {visible: false}` before a shell dialog and restore it when closing. The page is a native view and otherwise covers HTML overlays. To float something over the live page instead, open one of your own files with `ui.showOverlay {file}` and close it with `ui.hideOverlay`: the file is drawn as a transparent page covering the whole window, above the web page, and gets the same `window.skiff` bridge, `state` pushes and `ui.emit` events as the shell. The default command bar works this way. Pass `bounds: {x, y, width, height}` to confine the overlay to one rectangle, so the page around it stays clickable; a negative `x` or `y` measures from the right or bottom edge and follows resizes. Showing the same file again only moves it and leaves focus alone. There is one overlay, so showing another file replaces the first.
- `ui.setWindowButtons {visible: false}` hides the macOS window buttons while your shell has nothing to put behind them; a shell change or reload shows them again. Hidden buttons leave moving the window to a drag region (`-webkit-app-region: drag`) of your own.
- Treat host browser state as authoritative and rerender from `state` events. Input in progress may remain local; component preferences belong in declared settings or versioned component storage, not a duplicate tab/session model.
- Your Settings panel should draw every quick-panel entry from `settings.catalog {quickPanel: true, owner: "core"}` by its type (switch for `boolean`, number or text field, menu for an `enum`, a button with its status text for an `action`), write values back with `settings.set {<id>: value}`, run actions with `settings.run {id}`, and fetch the catalog again when it opens, after an action and when `state.settings` changes. Then a setting or action added to Skiff later (Auto-archive, Default browser, Update) reaches your panel without changing it. Layer files an entry under a page by its `section` (`tabs` on Browsing) and sends any other section to Skiff, so an entry with a new section still shows. Refetch it when `state.update.status` changes too, since `update` is an action that is available only when an update is ready. Show your own Update pill from `state.update` (visible when `status` is `ready`, click calls `updates.install`). Keep only what is specific to your interface (space name and color, agents, extensions, import) hand-coded. The bundled Layer in `shells/layer/` does this.
- `tab.favicon` is `''`, `../favicons/<name>` or a `data:` URL. The path form names a file the core saved under `favicons/` in the data dir, relative to the shell's `index.html`, so it works as an image `src` as it is. Incognito tabs get the `data:` form. Draw your own placeholder when it is empty, fails to load, or loads and draws nothing. Chromium accepts some broken ICO files without an error event or a rejected `img.decode()`, so Layer also checks that the icon has a visible pixel.
- A space with `incognito: true` is the temporary incognito space. A plain tab may carry `parentId`; Layer draws such tabs indented under their parent.
- The shell runs under a strict CSP: no inline scripts, no inline style attributes, no remote scripts. Images load only from the shell's own files and `data:` URLs (`img-src 'self' data:`), so a remote image URL does not load. Set CSS variables with `element.style.setProperty`.
- Page titles and URLs are untrusted. Use `textContent`, never `innerHTML`.

Theme: the variables at the top of `shell.css` (`--canvas`, `--ink`, `--accent`, `--control`) drive everything else through `color-mix`. `--accent` is set from the active space color. Light and dark defaults mix 14% of the space color into warm neutrals, with contrasting selected tabs. The incognito space uses a fixed dark gray theme. Imported backgrounds additionally paint the shell with `--space-background`, using their own semantic foreground rather than the default tint, without changing native page bounds. Manual color choices restore the default theme with the chosen accent.

The persisted/API space field is `background: {light?: layer, dark?: layer}`, where a layer is `{color: "#rrggbb"}` or `{color, colors: ["#rrggbb", ...], overlayColors: [...], intensity: 0..1}`. Colors may include an `aa` alpha suffix; each stop list is limited to 16. Only validated color values and finite intensity numbers are retained, never arbitrary CSS. An absent field is eligible for conservative backfill; `null` records a manual override. Invalid persisted data becomes `null`. Import fallback uses valid semantic or legacy colors when the gradient is malformed.

Rendering is an approximation of Arc's colors, not macOS vibrancy. Extended sRGB channels are clamped and rounded to 8-bit sRGB. Base colors run left to right across the window. Overlay colors run top to bottom over them. Stops are evenly spaced, and each color shows at two thirds of the stored intensity over the appearance's background color. Grain, wheel generation, translucency and window blur are not reproduced. Shell text is black or white, whichever contrasts more with the colors under the card. The colors are not washed out for legibility: a uniform veil is added only when that contrast would still be below 4.5:1. The stored source colors and intensity are unchanged.

Stock shell components follow the bundled source revision on update. `ui.resetShell` rebinds stock and legacy global role selections to the bundled Layer, but retains owned packages and independent custom and per-space bindings; component apply/revert provides explicit source revision history. An owned copy of a bundled component records its stock (`origin.id`, `origin.stockRoot`), the stock revision it was made from (`origin.baseRevision`) and a hash of its own source (`origin.sourceHash`, every file but `manifest.json` plus the manifest without its origin). At startup a copy whose workspace and active revision still hash to that record follows its stock when the stock changed: Skiff rebuilds the copy from the new stock source and activates it, keeping the previous revision for `components.revert`, its bindings, grants and settings. A copy follows only while its stock is the one currently selected from the same bundled source, and not when the new stock asks for capabilities the copy was never granted. A copy you edited, even if you never applied the edit, is never touched, and neither are copies of workspace components or migrated legacy source (`origin.type: "legacy"`, no recorded hash). Copies made before this record existed have no hash and stay as they are.

To look at Layer without Skiff, `node scripts/shell-preview.js shells/layer out.png` renders it in plain Chromium on a 1440 by 900 plain wallpaper, with a synthetic profile, stand-in pages at sample `tab.desk` rects, a frame view under each, named overlays, and a small core behind `desk.*`, `tabs.*` and `ui.setDesk`; add `--dark` for dark mode. It needs `npx playwright install chromium` once. Its steps run in the order given: `--click 'buoy:#buoy-main'` opens the expanded Buoy, `--drag "450,187 900,400 1436,450"` holds a drag mid-way (`--drop` releases it), `--click 'buoy:#buoy-tabs'` opens the tab list, `--emit new-tab --type lin` opens the command bar and types into it, `--size 560x600` changes the window. A selector (or `--eval` code) starting with `overlay:` targets the main overlay, `panel:` the panel's, `buoy:` the Buoy's, `tabs:` the tab list's, and `frame:<tab id>:` that window's frame. The preview stands for Skiff behind another app, so `--click 'tabs:.row-main'` shows just that tab's window. Its core also answers `settings.catalog` (from the real catalog), `settings.set`, `extensions.list` and `ai.agents`, so Settings shows the quick entries, one extension and two agents (`--click 'buoy:#settings-toggle' --click 'buoy:#settings-page-agents'`); `PREVIEW_UPDATE=1` has an update waiting.

## Desk shells

A shell folder with `shell.json` `{"window": "desk"}` gets a desk window instead of the app window: frameless, transparent, without a shadow, fixed over the work area of its display (never the menu bar or Dock), refitted when the displays change. Layer is one; a custom shell without it keeps the app window. Binding a shell of the other kind opens a new window of that kind and moves the open pages into it, still loaded; the app window's saved bounds are kept for the way back. `ui.setPageBounds` does nothing on the desk.

On the desk every tab may carry `tab.desk: {x, y, width, height, z, hidden?}` in window CSS pixels, saved with the tab; higher `z` is in front within its space. The window shows, for the active space, every ordinary tab (not a favorite, not pinned) that is not hidden, every other tab with a `tab.desk` that is not hidden, and the active tab, always in front. Placed windows stack by `z` above unplaced ones. A shown tab without a rect sits at a default: centred at 62% by 74% of the window (at least 240 by 160), 28px further down and right for each place in the space's tab order, starting over before it would leave the window; it is not saved until the shell places it. A tab opened while a desk window is open (from the command bar, `tabs.create`, a link or `archive.restore`) gets a rect at once: the last rect `desk.place` or `desk.tile` gave a tab of its host, 28px further down and right while a window shows at exactly that rect; else the largest part of the desk that no shown window or its frame's top inset covers, less an 8px margin, when that is at least 520 by 360; else the default. The last 200 hosts placed are kept in `deskHosts`, saved, incognito tabs never. A favorite or pinned tab activated on the desk gets that default rect and stays a window until hidden. Activating a tab, or clicking its page, shows it if hidden and brings it to the front; closing a favorite or pinned tab hides its window. State pushes carry `deskSize: {width, height}`, the window in CSS pixels, and `deskTop`, the frame's top inset, while a desk window is open. A space switch slides the shown windows like macOS Spaces over about 240ms, each page with its frame: the old space's leave the desk the way the switch goes (next space to the left, previous to the right, by `spaces.cycle`'s `delta` or else by space order) while the new space's come in from the other side, a switch mid-slide turns every window around from where it is, and a drag in progress ends; every space's shown windows load in the background after startup, so a first switch never waits for a page.

On a Mac, with a desk shell and Mission Control desktops that can be read (`src/desktops.js`, through the private CoreGraphics calls, off where they are missing), every desktop has a desk window of its own: none is visible on all desktops (`setVisibleOnAllWorkspaces`), so macOS slides each desktop's own pages in and out with it and never shows the pages of the desktop just left. A desk window holds the pages and frames of its desktop's tabs only. The desktop macOS reports after a switch gets its window, made at that moment for a desktop not seen yet (an empty desk until then), shown without taking the keyboard; the window of the desktop left stays as it is until that desktop is back, and goes when the desktop is removed or the shell changes. The Buoy and the tab list are float windows on every desktop, as they hold no page. Skiff never switches desktops: only the current desktop's window is raised or focused. Each tab carries `desktopId`, the id macOS gives its desktop, saved with the tab; a tab with none, or one whose desktop is gone (the ids can change across restarts), joins the current desktop. New tabs take the current desktop. `state.desktops: {current, list: [{id, number}]}` is runtime state in `state.get` and the event stream, never saved, and absent when the feature is off; `tabs.list` then also gives each tab its `desktop` number. The desk shows only the tabs of the current desktop, and Ctrl+Tab order (`tabs.cycle`, `tabs.select`) stays on it. When the desktop changes, a space whose active tab is on another desktop shows its latest tab here, or none. Exposé and the tab list show the space's tabs of every desktop under a "Desktop N" label. `tabs.activate` of a tab on another desktop moves it to the current one, since macOS has no supported way to switch desktops.

```sh
bin/skiff desk.place '{"x":40,"y":60,"width":900,"height":700}'   # the active tab; at least 240 by 160; shows it if hidden
bin/skiff desk.hide '{"id":"<tab-id>"}'                          # stays a tab of its space, keeps its rect
bin/skiff desk.show '{"id":"<tab-id>"}'                          # in front and active
bin/skiff desk.layouts                                           # {fill: {x, y, width, height}, center: ..., ...} for this desk
bin/skiff desk.tile '{"layout":"left"}'                          # the active tab at a layout, as desk.place does
```

The layouts are `fill`, `center` (60% by 75%), `left`, `right`, `top`, `bottom`, `left-third`, `center-third`, `right-third`, `left-two-thirds`, `right-two-thirds`, `top-left`, `top-right`, `bottom-left` and `bottom-right`, 8px from the desk's edges and from each other, with the frame's top inset free above each. Ctrl+Option+Left, Right, Up and Down tile the active window to that half of the desk, Ctrl+Option+Enter fills it and Ctrl+Option+C centres it (Ctrl+Super elsewhere); without a desk window they do nothing.

Hiding the active tab makes the frontmost window left in the space active, or none. A hidden page stays loaded.

A desk shell can draw around each window: `shell.json` `{"window": "desk", "frame": {"file": "frame.html", "top": 30, "right": 8, "bottom": 8, "left": 8}}` gives every shown window a transparent view of `frame.html?tab=<id>` at its rect grown by those insets (shell CSS pixels), stacked directly under that window's page, so window A's frame and page are both under window B's. Frames get the same `window.skiff` bridge and events as the shell, and `state` pushes while shown (one that shows again gets the current state), follow `preview`, keep their page while the tab exists and go when it closes.

Overlays can be named: `ui.showOverlay {file, bounds?, name?, focus?}` and `ui.hideOverlay {name?}`, `name` defaulting to `main`. Each name is its own view above every page and frame, `main` above the others. `focus: false` shows or moves an overlay without taking keyboard focus, `true` always takes it, and by default it is taken when the overlay is first shown or changes file. `ui.emit {name, data?, focus: false}` sends an event to the shell, its frames and overlays without focusing the shell.

`ui.showOverlay {..., float: true}` (desk windows only) puts an overlay in a window of its own instead of a view: frameless and transparent, above other apps' windows at the macOS floating level, on every desktop including full-screen apps, kept out of the Dock, the window list and Mission Control, and on macOS a non-activating panel, so showing, moving or clicking it never brings Skiff forward by itself. Its `bounds` are desk window CSS pixels, placed on the desk window's display, and it follows the desk window when the displays change. It is not part of the desk window, and it takes its own clicks. `hit: [{x, y, width, height}]`, in its own CSS pixels, lists where; everywhere else in it, such as the room for a shadow, clicks pass to whatever is below (without `hit` all of it takes them, and `ui.setDesk {capture: true}` holds them during a drag). It gets the same bridge, `state` pushes and events as other shell pages. `ui.hideOverlay` closes its window, and it closes when the shell reloads or a switch changes the kind of window. Whenever an overlay in the desk window or the shell takes the keyboard (`ui.showOverlay` focusing, or `ui.emit` without `focus: false`), the desk window comes forward first, so a click on a floating overlay while another app is in front opens what it asked for in front.

The shell reports its own clickable areas with `ui.setDesk {hit: [{x, y, width, height}, ...]}`; everywhere else that is not a page, a frame or an overlay, clicks pass through to the apps below. `ui.setDesk {capture: true}` keeps every click during a drag or resize, and `{preview: {id, x, y, width, height}}` moves a page and its frame live without saving (`null` ends it; a space switch ends it too and sends the shell `drag-cancel`). `{animate: false}` switches spaces without the slide, as reduced motion in the system settings does. `{only: [tabIds]}` brings just those windows of the active space forward: every other window's page and frame stay loaded but leave the desk window, and clicks there pass to the apps below. The active tab always joins the set (activating another tab adds it); moving or resizing a shown window keeps it; `null`, a space switch, or the last of its windows closing or hiding ends it. Every `state` push carries the set as `deskOnly` (`null` without one). These are not saved and reset when the shell reloads. `ui.inFront` answers `{front}`: whether Skiff is the app in front, that is the desk window, or a floating overlay clicked while the desk window had the keyboard, is focused. When the desk window gains focus while Skiff was not in front, and not from `ui.raise` or a shown overlay in the last 400ms nor a click on a window or overlay under the pointer, the shell gets `desk-activated`: Skiff was brought forward from outside, by the Dock or the app switcher. A mouse press on a page, a frame or the desk window, or another app taking the keyboard from Skiff, sends the shell `desk-press` (Layer closes its tab list on it).

`shells/layer` is the bundled desk shell and Skiff's only interface. Each window's frame view draws a 1px ring around its page (the space colour when active), a soft shadow and an ear on its top edge at the left (favicon and title, solid space colour when active), with hide and close buttons on hover. A tab the command bar just opened also shows a pill right of its ear (`offerLabel` in `common.js`, drawn by `frame.js`), kept clear of the ear's buttons and of the room other ears need. When a window in front (with its ear) or the Buoy covers that corner, the ear slides right along its own top edge until it is clear, shrinks its title to the widest stretch still showing if the whole ear does not fit, and hides only when no room for the favicon is left; ears glide to their new place as other windows are dragged. Drag the ear, or any empty part of the page's background (not text, links or controls), to move; double click the ear to fill and back; pinch on the ear to grow or shrink the window around its centre. The frame reaches 12px past the page on the sides and bottom, and all of it resizes: the edges, and 22px squares at the four corners; the edge (or both edges at a corner) a press would resize lights up in the space colour as the pointer reaches it. A press anywhere on the frame brings the window forward. Windows snap to each other and to the edges within 8px. Dragging to the left or right edge tiles to that half, the bottom edge to the bottom half, a corner to that quarter, and the top edge to the whole desk, except its middle third, which opens a strip of layouts (fill, centre, halves, thirds, two thirds and quarters, as `desk.layouts` gives them): hovering a cell previews it, letting go on it tiles the window there, and leaving the strip closes it. Letting go over the Buoy hides the window. The Buoy shows the space, the space's favorites as small icons in the card's order, the number of the space's active (ordinary) tabs, hidden ones included, and a plus. A small count after the space's name shows how many tabs and threads, in any space, are Unread, and goes when none are. Favorites: the active tab's is ringed in the space colour, hovering shows its title and a click brings its window forward with every other window of the space; once the pill would pass 60% of the desk width, the rest sit behind a +N that opens the card. Drag it anywhere, from a favorite too (it snaps to the edges, the corners and the top and bottom centre, and remembers its place). A two finger swipe across it, anywhere on the card or on a window's ear switches to the next or previous space as soon as it has moved 30px (a pinch on the ear still resizes, and scrolling up and down in the card scrolls its list). Each gesture switches once, however fast or long it runs, even when its momentum ends over another of them; a new touch or a swipe back starts the next one. A swipe also brings Skiff in front of other apps and gives the keyboard to the new space's front window. It is a floating overlay: it stays above other apps on every desktop, full-screen apps included. Its window is as big as the desk and takes clicks only on the pill (or on the open card), so everything else on the desk stays clickable. A click on the number opens the tab list next to it: a floating card of every space's open tabs, a heading per space, as the card's rows (favicon and title, the active one marked, hidden ones dimmed, a speaker on those playing sound); favorites and pinned tabs are listed once their page is loaded. Opening it brings nothing forward and changes nothing on the desk. A click on a row with another app in front shows only that tab's window, hidden or not, and brings Skiff forward with just that window over the other app; further picks while Skiff is in front add their windows; with the whole desk showing a pick just brings that window forward. The whole desk comes back from a click on the Buoy's name or a favorite, the card opening or a pick in it, exposé opening, a space switch, and Skiff brought forward by the Dock or the app switcher. The list closes on a pick, a second click on the number, Escape, any other press on the Buoy, another window coming forward, or once it has the keyboard, a click anywhere else; a two finger swipe over it switches spaces as the card does. Opening the Buoy is one motion: a click on its name or the plus, Cmd+T or Cmd+S makes the pill itself grow, in about 280 ms and settling as it arrives, from its place into a card in the middle of the desk, its outline, corner radius, background and space dot the same object all the way (the pill's content fades out as it grows and the card's fades in once the shape is most of the way there); closing runs it back to the pill's place. With reduced motion in the system settings it is a quick fade instead. The card is the command bar: its input takes the keyboard at once, and what is typed shows the bar's rows in place of the content below it (inline completion, tabs and archived pages, site search, the Ask row and agent mode, as described under Interface). With the input empty the card shows the panel's content: back, forward and reload, the favorites, the space's name with its window and tab count, then the space's tabs and agent threads in sections by bucket (see Tab buckets) in this order: Unread, Active, In Progress, Later (what pinned tabs were, with their folders) and Done, each with a small heading and its count and hidden while empty. The favorites stay an icon row above the space's name. A row is a window with an eye to hide or show it (a hidden window's row is dimmed, and dragging a row out of the card onto the desk puts its window there). A thread's row shows its sparkle icon and its agent's name, an Unread row a dot and a bolder title, an In Progress row a small spinner, and a Done row is dimmed and says when it will be archived ("archives in 5 h"). Drag a row onto another section, or onto the dashed area shown for an empty one, to move it there with `tabs.setBucket` at the spot you let go (In Progress takes no drops; Later's folders still take theirs), or press Alt+Shift+Up or Down at the edge of its section to step it into the next. A row whose bucket changes slides to its new place instead of jumping under the pointer. A trail child is indented under its parent only while both are in one section. The card ends with a footer with the space dots, new space, Agents, Archive, Settings and Tools. Settings, Archive, Agents and Import from Arc open inside the same card, in place of that content. Cmd+L opens the card on the current address (Cmd+J in agent mode), and `ui.emit` of `toggle-settings`, `toggle-archive`, `toggle-agents` or `import-arc` opens it on that view, or moves a card that is open to it; while it is open, Cmd+L, Cmd+J and those events switch what it shows without closing it. The card is transient: a pick (a tab or favorite, an archived tab, anything the bar opens) closes it, and so do Escape, a press anywhere outside it, the keyboard moving to another window or app, exposé opening, and a second Cmd+T, Cmd+S or click on the Buoy. It then shrinks back into the pill and the keyboard goes back to the page it came from. Opened from the Buoy while another app is in front, it brings Skiff forward and the whole desk with it.

Swipe two fingers up on the Buoy or on a window's ear for exposé, as a three finger swipe up does on macOS: the windows follow the fingers, each moving from its place toward its spot in rows spread across the screen in proportion to the swipe's travel (about 180 pixels takes them all the way). If the fingers stop or turn back before 72 pixels of travel, everything glides home; past that, when the swipe ends the rest of the way opens (momentum counts as travel, so a flick opens it). Each card is a picture of its page taken as the swipe starts, and hidden windows wait in a tray along the bottom with their icon. The desk dims at once; the title of the card under the pointer, or reached by the arrow keys, shows under it. The Buoy stays above exposé, as the Dock does over Mission Control, and no card lies under it; the expanded Buoy and the tab list close when it opens. Click a window, or pick one with the arrow keys and Enter, to bring it to the front (a hidden one is shown again: its tile grows into its window, which has no picture to show, and gives way to the page once it is drawn); the glide starts at once, without waiting for the core. Swipe down on the Buoy, an ear or anywhere over exposé, swipe up again, press Escape or click the empty background to leave with nothing changed; the windows glide back. A space with no windows says so, and the incognito space shows its own. A swipe that is mostly up or down never switches spaces, and a sideways one never opens exposé. Once a swipe has opened or closed exposé, its momentum tail does nothing more; a pause or a swipe the other way starts another, and one that lands while the windows are still going home opens exposé again once they have gone. Web pages take no part: a vertical swipe over a page only scrolls it. With reduced motion in the system settings the cards fade instead of gliding. Up and down follow the fingers: Skiff reads the Mac's scroll direction setting at launch, so it works with natural scrolling on or off.

An agent's tab is a window like any other: it starts hidden on the desk (it is in the card's list and the tab list, and shows when you pick it, or with `desk.show`), and wherever Layer draws a tab, its card row, tab list row, ear and exposé card, it carries the agent's name and a purple dot that pulses while the agent works, stays steady while it waits and turns green when it is done. A window an agent is working in has the control layer over its page (see Your agent above). The Buoy shows a chip after the space name that names the agents at work, such as "omp working" ("2 agents working" when the names are long, "omp idle" when none is working). A click on the chip opens a list of the agent tabs that are working, idle, asking for a tab or finished and unseen, each with its dot, title and agent; a click on a row shows that tab (`tabs.activate`) and closes the list. A red dot sits on the Buoy while any agent tab is unseen or asking, and goes when the tab is shown.

## Extensions

uBlock Origin is built in. At first launch Skiff downloads the latest release from GitHub into `extensions/` in the data dir and loads it into every space, the incognito one included; while that runs, Settings shows it as installing. A minute after each start, and every six hours after that, Skiff asks GitHub for the latest release and replaces the installed copy when the release is newer. The folder, and so the extension id and its storage, stay the same, so uBlock Origin's settings, filter lists and rules survive an update. A failed download is shown under the row in Settings and retried at the next check (five minutes later while nothing is installed). It cannot be removed; `SKIFF_BUILTIN_EXTENSIONS='[]'` in the environment turns the built-in set off, and a JSON list of `{name, release}` replaces it.

A page of a session does not start loading until that session's built-in extension is filtering: at startup (restored tabs included), for the first tab of a profile used for the first time, after an update replaced the extension and after a crash. The extension says it is ready by listening for `webNavigation.onBeforeNavigate`, which uBlock Origin does last in its start-up; after 15 seconds Skiff loads pages anyway and logs it, so a broken extension never stops browsing. Once a page starts, its first script waits (at most 300ms) until the extension's background page has taken that frame's `webNavigation.onCommitted`, so the scriptlets uBlock Origin injects from it run before the page's own scripts. An extension sees only the tabs of its own session.

Electron does not restart a background page that crashed or was killed, and the session would then filter nothing. Skiff watches every extension's background page and reloads that extension, in that session only, from the same folder (same id, storage untouched). Page loads in the session wait until it is ready again; open tabs are not reloaded. While it is down `extensions.list` and Settings show it as `restarting`; after five crashes within two minutes it stays down and shows `failed`.

Settings lists every extension with **Panel** (its popup over the page) and **Settings** (its options page, uBlock Origin's dashboard, as a tab). Cmd+Shift+U opens the first panel; `extensions.popup {id, bounds}` is the command behind it, and the panel closes when it loses focus. Other unpacked extensions or zips can be added from the API; an extension with the same name as one already added replaces it and keeps its storage:

```sh
bin/skiff extensions.list                           # built-in first: id, name, version, builtin, state, error, ...
bin/skiff extensions.update                         # run the built-in install or update check now
bin/skiff extensions.add '{"path":"/path/to/unpacked-extension-or.zip"}'
bin/skiff extensions.download '{"url":"https://example.com/extension.zip"}'
bin/skiff extensions.open '{"id":"<id>"}'          # its options page, as a tab
bin/skiff extensions.remove '{"id":"<id>"}'
```

Each extension keeps its own settings per profile session, so an imported Arc profile has its own copy of the filter lists and rules. Extension pages opened as tabs, such as uBlock's dashboard, are not kept across restarts. Zips are unpacked with `unzip`.

Electron does not implement all of Chrome's extension API. It runs content scripts, messaging, storage, alarms, scripting and blocking `webRequest` itself. Skiff adds what uBlock Origin needs on top: tab and navigation events, `tabs.get`, `query`, `create`, `remove`, `update`, `insertCSS` and `removeCSS`, a single-window `windows` API, and inert `browserAction`, `contextMenus` and `privacy` surfaces. There is no toolbar icon, badge or context menu, no `declarativeNetRequest` (so uBlock Origin Lite does not work, use uBlock Origin), and extensions that need other Chrome APIs may not work; check the console. Every `session.webRequest` listener in the core would silence extension listeners in that session, so the core has none.

Asking the agent, Settings > Agents and chat tabs run against `e2e/fake-agent.js`, a scripted ACP agent that streams replies (in markdown on cue), offers two models and two efforts, asks for permission, calls Skiff's MCP server, stalls, crashes on cue and reloads its sessions after a restart. Layer's exposé is opened and closed by wheel timelines on the Buoy, an ear and itself, and picked from by mouse and keyboard. Native sensitive-data consent cases run on macOS. Menu shortcuts are triggered by clicking their menu item from the main process, because synthetic key events do not reach the native menu. `e2e/agent-tabs.spec.js` covers agent tabs: one created over the API stays out of the window and the tab list, its hidden window is neither visible nor focused, the user's page keeps the keyboard while typing, and the page's interval and animation frame counters keep advancing; `ui.capture` by id returns a 1280 by 800 PNG whose sampled pixels show the page and `tabs.read` returns its text; peeking moves the same page into the window at the page bounds with a marker in the page intact and no new request, and leaving the peek parks it again, where it navigates, reads, captures and opens links into more agent tabs; it shares cookies with its space and the incognito space is refused; in the Layer shell a real click in the Agents list puts the window in front on the desk with its frame, a click on another window or the ear's hide button ends the peek, and the Buoy chip counts agent tabs live; and a second Skiff launched with no debugger attached, driven over the command API alone, shows the hidden page's timers and animation frames advancing and captures it, before and after a peek.

Each test owns a temporary home and a fresh Skiff profile, which opens in Layer, a local website, synthetic Arc metadata and synthetic databases. External requests and Keychain commands are blocked. Real Arc credentials and the user's Skiff profile are never used. Native consent responses are simulated; these tests do not prove actual Keychain access or password encryption. They cover wheel input, not physical trackpad finger recognition.

The imported-background scenarios import two real Arc themes, colors only, through synthetic Arc metadata. They read screenshot pixels: the hue at the window corners, and the contrast of the space title and every tab label against the pixels behind it. They also exercise appearance switching, restart and manual override, and assert unchanged shell and native page bounds. They attach shell images for visual review.

Prefer an unprivileged Linux user with a virtual display (`xvfb-run -a npm run test:visual`) so testing cannot interrupt someone's desktop. Never use `--no-sandbox`. Mac runs open real windows and are blocked unless `SKIFF_VISUAL_DESKTOP=1` is explicitly set; use that only when the desktop is available for testing. Screenshot baselines are separate for each OS and architecture; missing or changed baselines fail the normal command. Reviewed Linux baselines are included. Mac baselines still need a non-disruptive review session.

The suite captures the shell, while separately exercising the native webpage view, which does not appear in shell screenshots. The command bar is captured from its own overlay page, over a blank background; the page beneath it is asserted live, not drawn. Only an owned test window may be captured for a composed native screenshot.

Tests close their owned Electron process groups and remove temporary profiles. A shutdown that cannot be confirmed preserves its profile and fails. `test-results/` and `playwright-report/` are local, ignored artifacts; they are not packaged into the app. The test-only startup and consent override are excluded from packaged builds.

The selected-shell watcher compares file contents before reloading, so metadata-only file notifications do not reload it. Owned workspaces remain separate from active snapshots: edit the workspace and explicitly apply, rather than editing an active revision directory.

## Browser tools and limits

`ui.openTools` opens searchable settings, commands, history, downloads, profiles, nested folders, site permissions, component management, agent grants, transcripts and encrypted sync. Find in page, reversible reader mode, split view, user link peek, collapsible trails, persisted site zoom and crashed-page recovery are available. Memory saver is opt-in and reloads discarded pages; it does not preserve arbitrary JavaScript or scroll state.

Sync is manual and opt-in, using end-to-end encrypted records over a user-provided WebDAV endpoint or shared folder. It is not a hosted account service, and does not transfer cookies, passwords, component source, transcripts or private browsing. Pairing keys and transcript exports reveal sensitive material deliberately; keep them out of logs and shared folders. See the guide for conflict and unlock limitations.

The import skips Arc's archive and space icons, and there is no import from other browsers. Password import and deliberate filling are supported; saving newly entered passwords, automatic fill and password editing are not. There is no app icon or general failed-load error-page replacement.

Initial isolated Linux Electron smoke exercised find, reader, split, peek and history while preserving the page and its cookie. Broader native scenarios and review remain separate acceptance work; this is not a claim of complete validation or new macOS verification.
